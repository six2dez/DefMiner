# Phase 05 — UI Design Contract

> Visual and interaction contract for the DefMiner workspace. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**This is not a greenfield design.** Caido owns the theme. DefMiner's frontend is a guest inside
the Caido app, styled by a pass-through object it does not author, coloured by CSS variables the
operator can change, and prefix-wrapped so it cannot leak style into its host. Almost every value
below is therefore expressed as *the token to use*, not as a literal — and where the template asks
for a literal that DefMiner has no right to pick, the cell says what governs instead.

**The second thing this contract is about is not aesthetics.** Every string rendered on this page
came off the wire from a host that may be hostile. A secrets-inventory UI that leaks a secret into a
tooltip, an export or a log has defeated the tool. Rendering rules here are security controls with
the same standing as the backend's.

## Spacing Scale

Declared values, expressed as the Tailwind v3 utility that produces them. All are multiples of 4.

| Token | Value | Tailwind | Usage in DefMiner-authored markup |
|-------|-------|----------|-----------------------------------|
| xs | 4px | `-1` | Gap between a status badge and its text label; vertical padding inside a table cell |
| sm | 8px | `-2` | Horizontal padding inside a table cell; gap between adjacent filter controls; gap between triage buttons |
| md | 16px | `-4` | Padding inside the evidence panel and every dialog; gap between the table and the detail panel |
| lg | 24px | `-6` | Padding around a settings section; gap between settings groups |
| xl | 32px | `-8` | **Fixed virtualised row height** (`RecycleScroller :item-size="32"`) and the table header row height |
| 2xl | 48px | `-12` | Page toolbar height; sidebar-page top chrome height |
| 3xl | 64px | `-16` | Vertical breathing room above and below an empty-state block |

**Exceptions: none.** Every DefMiner-authored spacing value is one of the seven above.

**One honest note, and it is not an exception.** The vendored `Classic` `pt` object emits `px-3`
(12px), `px-5` (20px) and `py-3` (12px) *inside PrimeVue's own component internals*. Those are the
Caido theme's values, they are not authored by DefMiner, and changing them would mean forking the
theme. The scale above governs DefMiner-authored markup — page chrome, layout, tables, panels,
dialogs — which is the whole surface this contract can actually control.

**Why the row height is load-bearing and not a taste call.** `RecycleScroller` needs a fixed
`item-size` to compute scroll geometry. A variable row height — which is what happens the moment a
cell is allowed to wrap — degrades it to `DynamicScroller` and costs the 10,000-row responsiveness
target in Phase 5 success criterion 2. **Table cells never wrap.** That is why truncation in
`## Rendering Safety Contract` is mandatory rather than cosmetic.

## Typography

Four sizes, two weights. Sizes are Tailwind v3 utilities; the px column is their value at a 16px
root. **The effective px depends on Caido's root font-size, which DefMiner does not set** — the
utility class is the contract, the px is the expectation.

| Role | Size | Weight | Line Height | Applied to |
|------|------|--------|-------------|-----------|
| Label | `text-xs` / 12px | `font-semibold` (600) | `leading-normal` / 1.5 | Column headers, status badges, metadata keys in the evidence panel, settings field labels |
| Body | `text-sm` / 14px | `font-normal` (400) | `leading-normal` / 1.5 | Table cell text, evidence text, settings help text, all prose |
| Heading | `text-lg` / 18px | `font-semibold` (600) | `leading-snug` / 1.375 | Panel titles, dialog titles, settings section titles |
| Display | `text-2xl` / 24px | `font-semibold` (600) | `leading-tight` / 1.25 | The page title, and the empty-state heading. Nothing else. |

**Mandatory monospace rule — this is a security control, not a style preference.**
**Every string that originated from target-controlled bytes renders in `font-mono`.** That is:
extracted secret values (redacted or revealed), URLs, hostnames, endpoint paths, header values,
evidence snippets, error text quoting target content, and every export preview. Rationale: in a
proportional face `rn`/`m`, `l`/`I`/`1`, and `0`/`O` are visually identical, and an operator
triaging a hostname or a key cannot see the difference between a real value and a lookalike. Mono
is also what makes the truncation boundary in `## Rendering Safety Contract` visually honest.
Switching family is not a size or weight change and does not consume a slot above.

**Weights are exactly two: 400 and 600.** No `font-bold`, no `font-medium` in DefMiner-authored
markup. (`Classic` uses four weights inside PrimeVue's internals; same attribution as the spacing
note — the theme's, not DefMiner's.)

## Color

**No hex value appears in this contract, and no hex literal may appear in DefMiner's CSS or
markup.** That is not a stylistic preference: `caido.css` defines `--c-primary-*` / `--c-surface-*`
HSL triples **which the operator can customise**, and `@caido/tailwindcss@0.1.0` — inspected this
session — extends Tailwind's palette with exactly six roles, each backed by those variables:

```
primary | secondary | danger | info | success | surface     (steps 100…900)
        each → hsl(var(--c-<role>-<step>))
```

A hardcoded hex in DefMiner would survive the operator's theme change and turn into the one
unreadable element on their page. **Any hex literal in DefMiner frontend source is a contract
violation.**

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-surface-900` → `--c-surface-900` | Page background, table body, evidence panel body, dialog body |
| Secondary (30%) | `surface-800` / `surface-700`, borders `surface-600` | Page toolbar, tab strip, table header row, panel and dialog chrome, row separators, selected-row background |
| Accent (10%) | `primary-500` (hover `primary-400`, active `primary-600`) → `--c-primary-*` | The five elements listed below and nothing else |
| Destructive | `danger-500` (hover `danger-400`) → `--c-danger-*` | The four elements listed below and nothing else |

**Accent (`primary-*`) reserved for exactly these five:**

1. The single confirm button in a dialog — one per dialog, never two
2. The active tab in the workspace page nav
3. The keyboard focus ring
4. The 2px left-edge bar on the selected findings-table row
5. The "N new since you opened this" coalescing pill

**Accent is explicitly NOT used for:** severity or score badges, links back to a source request,
filter chips, sort indicators, triage buttons, the export button, tab hover, table row hover, or
any state that merely means "interactive". If it is a link or a button and it is not in the list
of five, it is `surface`-toned with an underline or a border.

**Destructive (`danger-*`) reserved for exactly these four:**

1. The confirm button in the **Create Caido Findings** dialog — because it is irreversible (FIND-01)
2. The confirm button in the **Export with raw values** dialog — because the file leaves the tool in cleartext (UI-06)
3. The `failed` scan-state badge, and analysis error text in the evidence panel (ERR-04)
4. The count in the partial-view banner when it includes failed artifacts

**Two semantic colours, declared as semantics rather than as a second accent:**

| Semantic | Token | Used for, and only for |
|----------|-------|------------------------|
| `success` | `success-500` | The `done` scan-state badge |
| `info` | `info-500` | The `partial` scan-state badge, the degraded marker, and the partial-view banner |

The justification the checker should weigh: these are not decorative accents, they are the visual
half of the OBS-02 degradation vocabulary. They map one-to-one onto the shipped `scan_state`
values and appear nowhere else.

**The Caido palette has no `warning` role** — verified against the plugin source this session. So
"degraded" cannot be a yellow. It is `info` plus a mandatory text label, which is the better answer
anyway:

**Colour is never the only carrier of meaning.** Every state that colour indicates also carries a
text label, and every score carries its number. Three reasons, in order of weight: UI-09 forbids a
degraded analysis being "silently presented as complete", and a colour an operator cannot
distinguish is exactly that silence; the operator can restyle `--c-*` and break any hue-based
convention; and red/green colour vision deficiency is common in the user population. **A severity
or score is rendered as a numeral plus a tier word. Colour is redundant reinforcement only.**

## Rendering Safety Contract

The load-bearing half of this phase. Everything here is derived from UISEC-01/02/03, UI-06 and
FIND-01, and each rule is testable.

### R1 — Text, never markup (UISEC-01)

- **`v-html` is banned in the DefMiner frontend.** Not "avoided" — banned by lint, as an error, on
  every file, with no per-line disable permitted. `@caido/eslint-config@0.10.0` already bundles
  `eslint-plugin-no-unsanitized`; add `vue/no-v-html` at `error` on top of it.
- Also banned: `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `new Function`,
  `eval`, and passing target-controlled strings to any `:style` binding or to a `href`/`src`
  attribute.
- **A link back to a source request is a Caido navigation call with a request ID, never an
  `<a href>` built from an extracted URL.** An extracted URL is data to be displayed, never a
  destination to be offered. If a "copy this URL" affordance exists it copies to clipboard.
- **Match highlighting inside an evidence snippet is done by slicing, not by markup.** The snippet
  is split at the byte offsets into three plain strings rendered into three sibling elements
  (before / match / after), the middle one carrying a background class. Building a `<mark>` string
  by concatenation and rendering it is precisely the defect this rule exists to prevent.

### R2 — Truncation and sanitisation (UISEC-03)

Applied to every target-controlled string before it reaches the DOM, in this order:

1. **Strip C0/C1 control characters** (`U+0000`–`U+001F`, `U+007F`–`U+009F`) except where the
   evidence panel is deliberately showing whitespace, in which case they are rendered as visible
   escapes (`\n`, `\t`), never as raw characters.
2. **Strip Unicode bidirectional overrides and isolates** (`U+202A`–`U+202E`, `U+2066`–`U+2069`).
   A hostile bundle can otherwise make `evil.com` render as `moc.live` in a hostname column — a
   spoofing vector against the very column the operator triages on.
3. **Truncate, grapheme-safe** — never split a surrogate pair or a combining sequence:
   - **table cell: 256 characters**
   - **evidence panel: 2,048 characters**, with the byte range of what is shown stated
   - **tooltips: no target-controlled content at all.** A tooltip is unbounded, unscrollable and
     escapes its container; it is the wrong element for a 4 MB literal. Detail goes to the panel.
4. Render with `white-space: pre` (so a value containing newlines cannot grow the fixed 32px row)
   and `overflow: hidden` with an ellipsis.

The full untruncated value is **never** placed in the DOM, never in a `title` attribute, and never
in a `data-*` attribute. "Copy full value" reads it from the store and writes it to the clipboard.

### R3 — CSV and JSON export (UISEC-02, UI-06)

- **CSV formula neutralisation:** any field whose first character is `=`, `+`, `-`, `@`, TAB
  (`U+0009`) or CR (`U+000D`) is prefixed with a single apostrophe before quoting. Then every field
  is quote-wrapped and internal quotes doubled. Both steps, in that order — quoting alone does not
  stop Excel.
- **Redacted is the default and is the pre-selected radio in the export dialog.** Raw requires
  actively choosing the second option and then confirming the `danger` dialog in
  `## Copywriting Contract`. There is no "remember this choice" for raw.
- JSON export applies the same redaction default and the same sanitisation as R2 to any field it
  emits; it does not need formula neutralisation but does need the control-character strip.

### R4 — Findings projection irreversibility (FIND-01, FIND-02)

- The projection surface shows **what will be projected, before it is projected** — a preview list
  the operator can review row by row.
- Entropy-only and hint-grade results are **not shown as projectable at all**. They are not merely
  unchecked by default; they are absent from the preview, and the surface states why:
  **"{n} results are entropy-only or hint-grade and are never projected to Caido Findings."**
- The irreversibility sentence appears at the point of action, in the dialog, not only in a
  settings help text. FIND-01's whole point is that this is the one action in the tool that cannot
  be undone.

### R5 — Server-side storage labelling (forward constraint)

Not a Phase 5 requirement — DEPLOY-02 lands in Phase 6 — but it is free to honour now and
expensive to retrofit: **any filesystem path the Settings surface displays is labelled "on the
Caido server" and is never presented as a path on the operator's machine.** Caido is client/server;
the backend may be a remote VPS or a container.

## Data & Interaction Contract

### Layout

A single sidebar page registered via `sdk.navigation.addPage()` plus a sidebar item (UI-01). Three
regions, top to bottom:

1. **Toolbar (48px)** — target/project name, the partial-view banner slot, the coalescing pill
   slot, and the **Export inventory** CTA.
2. **Tab strip** — one tab per entity class, plus **Health** and **Settings**. The entity classes
   are defined by Phases 3 and 4; this contract does not name them.
3. **Split body** — findings table on the left, evidence panel on the right. The panel is a
   persistent region, not an overlay: an overlay would force the operator to close it between rows,
   which is the wrong ergonomics for triaging thousands of items.

### Table contract (UI-02, UI-03, UI-07)

| Property | Value | Why |
|----------|-------|-----|
| Page size | **100 rows** per keyset page | `CODEX-CONTRAST.md` §4.7 budget. Never ship the whole result set to Vue. |
| Pagination | **Keyset (cursor)**, never `OFFSET` | `OFFSET` degrades linearly and drifts when rows are inserted mid-session — which they constantly are here |
| Virtualisation | `RecycleScroller`, fixed `item-size: 32`, buffer 200px | Fixed size is required for the 10,000-row target |
| In-memory window | **2,000 rows max**; older pages evicted forward-scroll, re-fetched by cursor | Bounds the renderer's memory the way the backend queue bounds its own |
| Sorting & filtering | **Server-side, always. Client-side sorting is banned.** | Sorting the 2,000-row window would silently sort a *subset* and present it as the whole set — a correctness defect that looks like a feature |
| Row click | Opens the evidence panel; does not navigate away | |
| Column shape | Fixed: `[state/score] [target-controlled value, mono, truncated] [last seen] [triage state]` + entity-specific columns | The entity-specific columns are **not specified here** — see below |

**The column lists for the entity tables are deliberately not fixed by this contract.** The entity
schemas are defined by Phase 3 (detection engine) and Phase 4 (passive intelligence core), neither
of which is planned. Inventing a column list now would be a guess that later contradicts the
schema. What *is* fixed and binding on every column added later: the four columns above are always
present in that order, exactly one column carries the target-controlled value, and every column
rendering target-controlled bytes obeys `## Rendering Safety Contract` R1 and R2.

### Event coalescing (UI-07)

- Backend→frontend events carry **an invalidation summary only**:
  `{ projectId, category, changedCount, newestId }`. **No findings payload, no bundle bodies.**
  The UI re-queries a page when it decides to.
- The frontend coalesces per category on a **500 ms trailing window**, capped at **2 UI reactions
  per second** across all categories.
- **While the operator has a row selected or the evidence panel open, the table does not re-order
  or re-render rows.** New counts accrue into the coalescing pill and apply on **Refresh**. Rows
  shifting under a cursor mid-triage is how an operator marks the wrong finding as a false
  positive — a mis-click here writes durable state.
- A frozen-looking page is almost always **the backend's single QuickJS thread being blocked by a
  large parse** (PITFALLS P3), not Vue. The Health tab therefore shows queue depth, dropped count,
  jobs in flight and max observed synchronous slice, so the operator can tell the two apart instead
  of filing "the UI hangs".

### Status vocabulary (UI-09, OBS-02)

Bound to the **shipped** `scan_state` CHECK constraint in
`packages/backend/src/store/migrations.ts` step v2 — this contract adopts those values rather than
inventing UI-only synonyms. OBS-02 formally owns the vocabulary in Phase 2; if Phase 2 changes it,
this table changes with it.

| `scan_state` | Label | Colour | Meaning to the operator |
|--------------|-------|--------|-------------------------|
| `pending` | **Queued** | `surface-400` | Not started |
| `running` | **Analysing** | `surface-400` | In flight |
| `done` | **Complete** | `success-500` | Every byte inspected |
| `partial` | **Partial** | `info-500` | Stopped early — results are a floor |
| `failed` | **Failed** | `danger-500` | Nothing was inspected — not the same as "no findings" |

### Triage & suppression (OPS-01…04)

- Triage states form a closed vocabulary in the same snake_case style as `scan_state`:
  `new` · `reviewed` · `false_positive` · `accepted`.
- Triage is **keyed on a stable entity identity, never on `detector_set_hash`** — otherwise a
  corpus bump silently discards every triage decision the operator made, which is exactly what
  OPS-04 forbids. When a re-analysis re-raises a triaged finding, the panel says so with the
  preserved state and its original date (copy row in `## Copywriting Contract`).
- A suppression rule is created **from a finding**, in one action, and lists its scope
  (this value / this pattern / this host) explicitly at the point of creation. The Suppressions
  list is a first-class surface: rules are visible, attributed to the finding that created them,
  and removable. **Suppression is reversible; Findings projection is not.** That asymmetry is
  visible in the confirmation ceremony each one gets.

## Visual Hierarchy

**Focal point on the workspace page:** the findings table's leading column pair — the **score
numeral + tier word** followed by the **redacted mono value**. Those two are what the operator's
eye must land on, because the entire product thesis is "signal quality high enough that the
operator reads every finding". Everything else on the page is `surface`-toned chrome that
deliberately recedes.

Order of visual weight, strongest first:

1. Score numeral + tier word (Label weight 600, the only numerals on the row)
2. The target-controlled value in `font-mono`
3. Status badge — colour + word
4. Last-seen, triage state — Body weight 400, `surface-400`
5. Toolbar and tab chrome — `surface`, no accent except the one active tab
6. The single accent element on screen at a time — usually the focus ring

**Accessibility rules that are part of this contract:**

- **No icon-only action anywhere.** Every action carries a text label. Destructive actions
  additionally never appear as an icon.
- Every interactive element is keyboard-reachable and shows the accent focus ring (accent use #3).
  A 10,000-row triage surface is a keyboard surface.
- The virtualised table exposes proper row/grid semantics; virtualisation must not silently strip
  them, and screen-reader row counts must reflect the true total, not the 2,000-row window.
- No meaning is carried by colour alone — restated here because it is an accessibility rule as well
  as the UI-09 rule.

## Registry Safety

**shadcn is not in use and must not be introduced.** It is a React component registry; this stack
is Vue 3 with PrimeVue pinned exactly at `4.1.0` by `@caido/primevue@0.3.3`'s peer dependency.
`components.json` is absent from the repo and is expected to stay absent. The shadcn initialisation
gate was therefore executed and resolved as **not applicable** — it was not skipped, and it was not
put to the user, because `STACK.md` settles it.

**Third-party registries used: none.** There is no registry-fetch step in this stack; every
component comes from a version-pinned npm dependency already enumerated in `STACK.md`.

| Registry | Blocks Used | Safety Gate |
|----------|-------------|-------------|
| shadcn official | none — shadcn not in use (React-only; PrimeVue is pinned) | not applicable |
| third-party registries | **none declared** | not applicable — no registry fetch exists in this stack |

planning.

| # | Decision | Default this contract ships under |

| D1 | Does a revealed secret value appear in the table cell, or only inside the evidence panel? | **Panel only**, revealed by an explicit per-finding action, auto-re-redacted when the panel closes or on project change. A revealed value in a table cell is a value that ends up in a screenshot. |
