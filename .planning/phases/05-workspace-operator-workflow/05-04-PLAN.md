<objective>
Publish, upward to Phases 3 and 4, the read contract that Phase 5's UI needs from an entity table —
and write the deferral register that keeps every already-locked decision alive until the pass that
implements it.

Purpose: D-05 settles that Phase 5 does not re-sequence and does not invent Phase 4's schema.
Instead it authors the interface it is the only consumer of. That is four columns, a cursor tuple,
an invalidation category, a score-explanation frame and an evidence-panel frame — the last of which
is exactly what `05-UI-SPEC.md` checker FLAG F1 asked for and left open.

The second half matters as much: seven requirements (UI-03, UI-04, OPS-01, OPS-02, OPS-04, FIND-01,
FIND-02) are deferred by D-05(3). Each carries decisions the operator has already made — D-01's
dedupeKey composition, D-02's request-attachment rule, D-03's per-row opt-in. A deferral that does
not carry its decisions forward is a decision that gets re-litigated wrong.

Output: a TypeScript type in `packages/engine/` (SDK-free, so Phases 3 and 4 can import it without
a Caido dependency), a companion document, and a deferral register with a blocker and an unblocking
phase per requirement.
</objective>
