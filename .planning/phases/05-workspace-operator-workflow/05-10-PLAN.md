<objective>
Build the retry path over the shipped analysis states, and the evidence panel frame it is invoked
from — the persistent split region, the loading skeleton that does not collapse, the failure copy
that says in words what a failed analysis means, and the artifact-version line.

Purpose: this is the buildable half of the evidence surface. The byte offsets and the score
explanation both live in tables and vocabularies that do not exist yet, and inventing them is exactly
what the design contract declined to do for exactly this reason. The frame, though, is buildable now,
and building it now means the deferred pass adds fields rather than restructuring a region.

The retry path is the other half and is fully buildable: the analysis table carries the five-state
vocabulary and the failure copy's action is precisely the requirement. It also matters more than it
looks — the projection surface in the deferred pass turns a blocked row into a projectable one
through this action, so a missing retry makes a later blocker permanent.

Output: `retry.ts` and its RPC, `EvidencePanel.vue`, and the split-body wiring.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| analysis error text -> panel copy | The one place a hostile artifact's own message would most naturally be echoed into the operator's view |
| operator retry -> analysis state transition | A state write reachable from the UI; the guard must be in the statement, not in the caller |
| evidence snippet -> panel DOM | Target-controlled bytes at the larger of the two caps |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-50 | Tampering | a running analysis reset underneath itself by a retry | high | mitigate | The state guard is a list constraint inside the update statement rather than a caller-side check, and the running-state case is asserted to change nothing (task 1) |
| T-05-51 | Information Disclosure | a target-controlled error message echoed into panel copy | high | mitigate | The failure reason rendered is a DefMiner-authored reason code; the backend already redacts before truncating, and the panel interpolates no target-controlled string into a sentence (task 2) |
| T-05-52 | Information Disclosure | evidence content leaking into a tooltip or an attribute | high | mitigate | The panel asserts, per test, that no node carries a title attribute or a data-prefixed attribute; the static gate reports both classes anywhere in the package (task 2) |
| T-05-53 | Tampering | a retry write against a row in another project | high | mitigate | Project column in the update predicate, enforced by the SQL gate and by a behavioural wrong-project test (task 1) |
| T-05-54 | Tampering | the panel opening without setting the flag the coalescer reads, exposing the operator to a row shift mid-triage | medium | mitigate | The wiring test emits an invalidation summary with the panel open and asserts zero reactions and a non-zero pending count (task 3) |
| T-05-55 | Repudiation | a retry reported as succeeded that did not persist | medium | mitigate | Write-then-read: the resulting state is read back after the write because this driver cannot report what it wrote, and the action never optimistically shows a state that was not persisted (tasks 1, 2) |
