<objective>
Build the configuration and diagnosis half of the workspace: a settings surface over the shipped
three-level resolution, the retention bounds the shipped defaults record as owed to this phase, the
health counters that let an operator tell a blocked backend from a slow renderer, and the visible
refusal surface a build that will not run on an unmeasured host owes the operator.

Purpose: three shipped debts are discharged here, all of them recorded in the code as owed to this
phase. The settings module was written with three resolution levels specifically so this phase could
add an operator-wide default with a per-project override without touching a call site. The two
retention defaults each carry a comment saying there is no way to change them until this phase. And
the compatibility refusal path records that its visible surface is owed here — right now a refusing
build says so in a log line and in one remote-procedure response, which is the obscure failure the
compatibility requirement forbids.

The health surface is not diagnostics decoration: a frozen-looking page is almost always the
backend's single thread blocked by a large parse, and without these counters the operator files a
report about a hanging interface instead of reading a queue depth.

Output: the settings and health endpoints, `SettingsPanel.vue`, `HealthPanel.vue`,
`CompatRefusal.vue`, and the tab wiring.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator-entered bound -> the retention sweep | A bound is the only control over what the sweep deletes; a bad one deletes everything |
| server filesystem path -> the operator's mental model of where their data is | The host is client and server; a server path shown as local sends them to the wrong disk |
| backend counters -> the health strip | The only surface whose content is entirely DefMiner-authored, and it must stay that way |

| T-05-63 | Denial of Service | a retention bound of zero, empty or non-numeric silently applied, deleting the operator's history | high | mitigate | Validation at the write edge in addition to the shipped defensive read, with four rejection cases asserted and a distinguishable reason each (task 1) |
| T-05-64 | Information Disclosure | a server filesystem path presented as a path on the operator's machine | medium | mitigate | The path is labelled as being on the server, truncates from the left, carries no title attribute, and exposes its full value only through the copy action (task 2) |
