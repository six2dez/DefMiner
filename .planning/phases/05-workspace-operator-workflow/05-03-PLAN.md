<objective>
Write the three pure, SDK-free primitives that every rendering and export surface in this phase
depends on: the sanitise pipeline (strip then truncate, grapheme-safe), the CSV field rule
(neutralise then quote, in that order), and the single hostile-content fixture that four surfaces
assert against.

Purpose: `05-UI-SPEC.md` calls these security controls with the same standing as the backend's, and
the architectural responsibility map puts truncation on the backend *and* re-asserted on the
frontend, control-stripping at the DOM sink, and CSV serialisation on the backend only. One
implementation in `packages/engine/` is what makes "the same bytes everywhere" true rather than
aspirational — and the engine package is SDK-free by construction, enforced by four independent
mechanisms, so these run under plain vitest with no Caido and no DOM.

Output: `sanitise.ts`, `csv.ts`, `hostile.fixture.ts` and their specs, with explicit `exports`
entries.

    - A string containing `U+0000`, `U+001F`, `U+007F` and `U+009F` returns with all four removed.
    - A string containing `U+202A` through `U+202E` and `U+2066` through `U+2069` returns with all eight removed.
    - A string whose 257th character begins a surrogate pair, truncated at the table-cell cap, returns 256 graphemes and does not end in a lone surrogate.
    - A string built from base characters each followed by a combining mark, truncated, never ends between a base and its mark.
    - A string of exactly the cap length returns unchanged and reports `shown === total`.
    - A string one character over the cap reports `shown < total` and `total` equal to the stripped length.
    - The empty string returns the empty string with `shown === 0` and `total === 0`.
    - A string whose only content is control characters returns the empty string with `total === 0` — stripping runs before length is computed.
    - A 4 MB single-line string truncates and the call returns within a bound the spec asserts.
    - A string containing `\n` and `\t` returns with them removed by the default path, and returns them as the two-character visible escapes only when the escape mode is explicitly requested.

  <action>
    Create `packages/engine/src/sanitise.ts` opening with the banner pattern `decode.ts` uses. The
    banner states the two facts this phase turns on: **strip before truncate**, because truncating
    first can leave a half-stripped sequence at the boundary; and that `Intl.Segmenter` is a browser
    API and is **not** in Caido's QuickJS global set — Phase 0's capabilities measurement lists 100
    globals with no `Intl` entry — so the grapheme path is frontend-only and the backend caps by
    code point. Record that as a measured absence with its provenance, the way `decode.ts` records
    its own.

    Export two named caps as constants with their rationale from `05-UI-SPEC.md` R2:
    `TABLE_CELL_MAX_GRAPHEMES = 256` and `EVIDENCE_PANEL_MAX_GRAPHEMES = 2048`. No default
    parameter — a caller must name which surface it is truncating for, so a panel cap cannot leak
    into a cell by omission.

    Export the two strip regexes as named constants (`C0_C1_CONTROLS`, `BIDI_OVERRIDES_ISOLATES`)
    so the frontend AST gate and the export serialiser can assert they are the same ones.

    Export `forDisplay(raw, maxGraphemes)` returning `{ text, shown, total }`. Order: strip C0/C1,
    strip bidi, compute `total` from the stripped string, then segment and truncate. Where
    `Intl.Segmenter` is present, segment with granularity `grapheme`; where it is absent, fall back
    to code-point iteration and record on the returned object nothing that distinguishes the two —
    the fallback is a capability difference, not an API difference. The returned object must not
    carry the source string or the remainder.

    Export `forEvidence(raw, maxGraphemes)` — the same pipeline but with C0/C1 rendered as the
    two-character visible escapes `\n` and `\t` instead of removed, for the one surface that is
    deliberately showing whitespace. Escapes are inserted *before* length is computed, so a value
    of newlines cannot silently occupy zero of the cap.

    Add `"./sanitise": "./src/sanitise.ts"` to `packages/engine/package.json` `exports`.

    merely being slow.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| target-served bytes -> extracted string -> DOM text node | Every string these primitives handle originated on a possibly-hostile host |
| target-served bytes -> extracted string -> CSV field -> the operator's spreadsheet | The export leaves the tool and is opened by software that executes cell contents |
| `packages/engine` -> the Caido SDK | The boundary that must stay closed; these modules run under plain vitest precisely because it is |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-10 | Tampering | CSV export opened in a spreadsheet | high | mitigate | `csvField` applies apostrophe prefix then quote wrap, in that order, with the ordering itself asserted at character index rather than merely the apostrophe's presence (task 2) |
| T-05-11 | Spoofing | a hostname column rendering right-to-left because of a bidi override | high | mitigate | `BIDI_OVERRIDES_ISOLATES` stripped in `forDisplay` before truncation; the hostname-reversal case is in the fixture and is iterated by both specs (tasks 1, 3) |
| T-05-12 | Denial of Service | a multi-megabyte single-line value reaching a renderer | high | mitigate | Truncation at a named cap with no default, plus an asserted elapsed-time bound on the 4 MB case so a quadratic implementation fails the spec (task 1) |
| T-05-13 | Information Disclosure | the untruncated value reachable from the object handed to a sink | medium | mitigate | The returned object's own enumerable keys are asserted to be exactly `text`, `shown`, `total` (task 1) |
| T-05-14 | Tampering | a control character used to hide a dangerous CSV lead | medium | mitigate | Control stripping runs before the lead test, and that specific ordering has its own fixture (task 2) |
</threat_model>
