# Phase 07 — UI Design Contract

> Visual and interaction contract for the recovered-source drill-down, the source tree, the source
> viewer, the position readout and the manifest export. Generated by gsd-ui-researcher, verified by
> gsd-ui-checker.

**This document EXTENDS `05-UI-SPEC.md` and `06-UI-SPEC.md`; it replaces neither.** Phase 5's
contract was approved 2026-08-28 (6/6 dimensions), Phase 6's on 2026-08-31 (7/7), and 28+ frontend
modules ship against them. **Every value in them is inherited verbatim** — the stack pins, the
seven-value spacing scale, the four sizes and two weights, the mandatory `font-mono`, zero hex
literals, the six Caido colour roles, R1–R5, the table and coalescing contracts, and the two closed
status vocabularies. Where this document says nothing, those contracts govern.

**Nothing here is greenfield and nothing here is a taste call.** `07-CONTEXT.md` locks
twenty-four decisions and `07-RESEARCH.md` settles seven of the eight open items from evidence in
the shipped tree. This contract's job is the residue: the four places a locked decision names a
surface without fixing its shape, and the one place — O-07's fifth separation mechanism — where a
Phase 5 rule genuinely breaks and needs a replacement rather than an exemption.

**The one thing that makes this phase different from every phase before it.** The source viewer
renders **the most hostile data this product has ever put in the DOM**: target-controlled bytes, at
megabyte scale, in a component whose entire job is to display them faithfully. D-18 (virtualise) and
D-19 (no highlighting, plain monospace) exist to keep that surface as small as it can be while still
delivering the feature, and **R1's "text, never markup" is doing the load-bearing work.** Every
rendering rule below is a security control with the same standing as the backend's.

Four sections carry the deltas and nothing else:

- `## Three Vocabularies Now` — O-07's answer, and the replacement for the separation mechanism
  that breaks.
- `## New Surfaces` — the five surfaces D-21, D-18, D-16 and D-20 add.
- `## Amendments to 05-UI-SPEC.md` — three places the upstream contract's own text must change.
- `## Named Conflicts` — the two places a shipped rule could not accommodate a Phase 7 surface,
  each stated with its evidence rather than worked around quietly.

## Spacing Scale

**Inherited verbatim from `05-UI-SPEC.md § Spacing Scale`.** Seven values — 4 / 8 / 16 / 24 / 32 /
48 / 64 — expressed as Tailwind v3 utilities. Restated here only as the mapping onto Phase 7's
surfaces, because the checker's Dimension 5 reads this section.

| Token | Value | Tailwind | Phase 7 usage |
|-------|-------|----------|---------------|
| xs | 4px | `-1` | Gap between a tree row's label and its producibility word; gap between a code line's truncation marker and the text it follows |
| sm | 8px | `-2` | **The tree's per-depth indent step** (`pl-2` per level); horizontal padding on every button on these surfaces (`px-2 py-1`, matching every shipped button); gap between the line-number gutter and the code text |
| md | 16px | `-4` | Gap between the tree column and the viewer column (`gap-4`, the same utility the shipped split body uses); left margin separating each drill-down header action from the one before it (`ml-4`, matching the shipped Export button) |
| lg | 24px | `-6` | **The fixed virtualised source-line height** (`h-6` — see the note below and amendment A5); padding inside the drill-down's empty-state and tombstone blocks (`p-6`, matching every shipped section) |
| xl | 32px | `-8` | **The fixed virtualised tree-row height** — `TABLE_ROW_HEIGHT_PX`, unchanged and re-read from `safety/display.ts`, never restated |
| 2xl | 48px | `-12` | The drill-down header strip, the tree column header, the viewer column header and the position strip — **all four at `h-12`**, the same utility `HEALTH_STRIP_HEIGHT_CLASS` already resolves to |
| 3xl | 64px | `-16` | Vertical breathing room around the source browser's empty state; **the maximum tree indent** (8 depth levels × the `sm` step); the line-number gutter's fixed width (`w-16`) |

**Exceptions: none.** Every Phase 7 spacing value is one of the seven above, and this phase is the
first to spend all seven.

**The second fixed row height is a real addition and it is declared, not smuggled.** `05-UI-SPEC.md`
assigns the `xl` step to "Fixed virtualised row height", singular, because Phase 5 had one
virtualised list shape. Phase 7 has two, and a code line is not a table row: at `text-sm` /
`leading-normal` the line box is 21px, so a 32px row buys 11px of dead space per line and costs the
operator a third of the source they could otherwise see on screen. **`SOURCE_LINE_HEIGHT_PX = 24`
(the `lg` step) is declared beside `TABLE_ROW_HEIGHT_PX`, and `h-6` is added to
`table-contract.ts`'s `ROW_HEIGHT_CLASSES` as a LITERAL** — that map's own error message demands a
literal because Tailwind's JIT scans source and `h-[${n}px]` emits nothing. `TABLE_ROW_HEIGHT_PX` is
byte-unchanged and the tree rows still read it. Carried upstream as amendment A5.

**Depth indent is capped and the cap is on the scale.** Eight levels at the `sm` step reaches the
`3xl` step exactly. A node deeper than eight holds the 64px indent and does not grow further — its
parent chain is visible above it, and an indent that could grow without bound in a `w-1/4` column is
an indent that eventually leaves no room for the label the operator came to read.

## Typography

**Inherited verbatim from `05-UI-SPEC.md § Typography`: four sizes, two weights (400 / 600), the
per-role line heights, and the mandatory `font-mono` security control.** No new size, no new weight,
no new family.

| Role | Size | Weight | Line Height | Phase 7 application |
|------|------|--------|-------------|---------------------|
| Label | `text-xs` / 12px | `font-semibold` (600) | `leading-normal` / 1.5 | The tree column header and its count line; every button label on these surfaces; **the line-number gutter** (in `surface-400` — see below); the producibility word; the per-line truncation marker; the tree node's display notes |
| Body | `text-sm` / 14px | `font-normal` (400) | `leading-normal` / 1.5 | **Every recovered source line**, in `font-mono`; every tombstone sentence; the position readout; the empty-state body; all prose |
| Heading | `text-lg` / 18px | `font-semibold` (600) | `leading-snug` / 1.375 | The viewer column header's source label — in `font-mono`, sanitised, at the table-cell cap. Nothing else. |
| Display | `text-2xl` / 24px | `font-semibold` (600) | `leading-tight` / 1.25 | The source browser's empty-state heading only. Nothing else. |

**`font-mono` on Phase 7 surfaces — three strings carry it, and all three are target-controlled.**
This is the phase the rule was written for.

1. **Every recovered source line.** It is the developer's own bytes, at megabyte scale, and telling
   `l` from `1` from `I` in a recovered credential or hostname is the entire point of reading it.
2. **Every `sources` display label**, in the tree and in the viewer header. It carries `webpack://`
   schemes, `..` segments and absolute paths — evidence about how the bundle was built (D-06) — and
   it is the string a hostile map most wants to make look like something it is not.
3. **Every digest** — the parent artifact's, the map's, the source's — for the reason
   `ArtifactsTable.vue`'s header already gives: `0`/`O` and `l`/`1` are the same picture in a
   proportional face, and two digests differing in one of them are indistinguishable.

**Nothing else on these surfaces is mono, and the line-number gutter is the deliberate exclusion.**
Line numbers are DefMiner-computed integers. Applying mono to them would dilute the signal the rule
exists to carry — that mono means *this text came from somewhere I do not control* — on the one
surface where that signal matters most. Alignment is solved geometrically instead: the gutter is a
fixed `w-16` (`3xl`) column, `text-right`, so the digits' right edge is fixed and the left edge's
jitter falls into padding where it is invisible.

**The gutter recedes by colour, not by weight.** It renders at Label role in `text-surface-400` —
the established neutral level-4 tone. Dropping it to weight 400 would be a fifth size/weight pairing
and there are exactly four.

**Weights remain exactly two: 400 and 600.** No `font-bold`, no `font-medium`.

## Color

**Inherited verbatim from `05-UI-SPEC.md § Color`: the six `@caido/tailwindcss@0.1.0` roles, zero
hex literals, `surface-400` as the neutral level-4 tone, and colour never as the sole carrier of
meaning.** Any hex literal in DefMiner frontend source remains a contract violation.

| Role | Value | Phase 7 usage |
|------|-------|---------------|
| Dominant (60%) | `bg-surface-900` | The drill-down body, the tree column, the viewer's code area — unchanged from every other tab |
| Secondary (30%) | `surface-800` / `surface-700`, borders `surface-600` | The three `h-12` header strips and the position strip; the tree column's right border; the line-number gutter's background (`surface-800`); **the selected tree node's and the selected code line's background (`surface-700`)** — which `05-UI-SPEC.md` already names under this role as "selected-row background" |
| Accent (10%) | `primary-500` | **The five reserved uses, unchanged. Phase 7 consumes exactly ONE of them — the keyboard focus ring (use #3) — and adds NONE.** |
| Destructive | `danger-500` | **Five named elements, unchanged. Phase 7 consumes use #2 (the Export-with-raw-values confirm) when the manifest is exported raw, and ADDS NONE.** |

**Accent: Phase 7 is the first phase to add nothing and to consume almost nothing.** The selected
tree node and the selected code line are `surface-700` backgrounds, **not** the 2px `primary-500`
left-edge bar of accent use #4 — that use names the findings-table row and this contract does not
widen it. The drill-down's Back, Save and Export controls are `surface`-toned with a border, exactly
as `05-UI-SPEC.md`'s not-list requires of "the export button" and of "any state that merely means
interactive". **Nothing on these surfaces is accent-toned except a focus ring**, which is the
strongest available statement that this page is for reading.

**Destructive: nothing here is irreversible.** Saving one source is a browser download of bytes the
operator chose to open — it is not the raw-values ceremony's subject and it does not get a `danger`
dialog; the reasoning is in `## Copywriting Contract`. A raw manifest export **is** that ceremony's
subject and reuses the shipped dialog unchanged rather than forking it.

**Semantics: Phase 7 renders neither `success` nor `info`, on any new surface.** The analysis state
is not rendered inside the drill-down at all — it lives at the artifact level, on shipped surfaces
(`## Three Vocabularies Now`).

**Producibility is `surface-400` and nothing else. It consumes no chromatic role.**

This is the load-bearing colour decision of the phase and it is a refusal, not an omission. `info`
would have been the obvious reach — `05-UI-SPEC.md` assigns it to "the degraded marker" — but that
clause is bound to the **analysis** vocabulary (`partial` badge, degraded marker, partial banner),
and painting a producibility state with the analysis vocabulary's degradation colour is precisely
the cross-vocabulary confusion `contract.ts:88-120` spends thirty lines refusing. `danger` is worse:
it is reserved for five named elements and a tombstone is not an error. **A tombstone is neither
good news nor bad news — it is an absence**, and `surface-400` is the tone this codebase already
uses for states that are neither (`pending`, `running`, `discarded`). Carried upstream as amendment
A6, which narrows 05's clause so no later vocabulary can claim `info` by reading it generically.

**Colour is never the only carrier.** Every producibility state that renders at all renders a word,
and the state that is fine renders nothing at all.

## Three Vocabularies Now — How Producibility Is Kept Apart

`contract.ts:88-120` is an essay on why `SCAN_STATES` and `SCAN_LIFECYCLE_STATES` are two closed
vocabularies that share the word "scan" and the literal member `running`, and why merging them would
give the compiler nothing to check at exactly the sites where a wrong state is invisible. **Phase 7
adds the third**, and O-07 settled that this is correct — the project's actual rule is *one
vocabulary per subject, each closed, each with a mechanical every-member-has-a-case gate*, and the
repo already ships eleven of them.

**The two axes, stated so a verifier cannot collapse them:**

- **`analyses.scan_state` answers: did DefMiner finish looking at these bytes?** A refused,
  truncated or malformed map is `partial` with its redacted 240-char error (D-11).
- **`producibility` answers: can DefMiner still show you these bytes?** It is producible until a
  derivation attempt proves otherwise, and that outcome then sticks to the row (D-22, D-23).

All four combinations are reachable and meaningful — `done`/producible (normal), `done`/gone (the
map parsed fine, Caido lost the request), `partial`/producible (the map was over the bound; there is
nothing to produce anyway), `partial`/gone (both). **One column cannot express four states across
two axes without inventing product names for combinations**, which is the "nothing found versus
analysis broke" confusion ERR/OBS-02 exists to prevent, relocated into a new surface.

**The five mechanisms, applied:**

| # | Mechanism | Phase 7 |
|---|-----------|---------|
| 1 | **Adjacent declaration** | `SOURCE_PRODUCIBILITY_STATES` is declared in `packages/engine/src/contract.ts` **immediately after `SCAN_LIFECYCLE_STATES`**, with a note in the same register naming the third collision. The collision is then visible at the point of declaration rather than discovered at a call site three packages away. |
| 2 | **Distinct column name** | The column is **`producibility`**. Never `state` (taken by `scans`), never `scan_state` (taken by `analyses`). Both those names would have accepted a wrong value silently. |
| 3 | **No shared or prefix label** | **Nine operator-facing state words are already in use**: Queued · Analysing · Complete · Partial · Failed (analysis) and Scanning · Suspended · Finished · Discarded (lifecycle). The producibility words are **Gone** and **Changed**. Neither shares a stem with any of the nine, neither is a prefix of any of them, and none of them is a prefix of these. *Missing*, *Lost* and *Incomplete* were rejected: none is clearly safe against **Partial** in an operator's peripheral vision. |
| 4 | **Own presentation map, renderer and marker** | A third file, `components/source-producibility-presentation.ts`, a third renderer, `components/ProducibilityMark.vue`, and a third marker, `data-defminer-source-producibility`. **`StatusBadge`'s prop is NOT widened** and `ProducibilityMark` is not a badge — see mechanism 5. |
| 5 | **No surface renders both** | **BREAKS.** The replacement is below. |

### The replacement for mechanism 5

The drill-down renders the parent artifact's analysis state and each recovered source's
producibility in the same view. Separation therefore has to be carried by **layout, level and
label**, not by absence. Four binding requirements:

1. **They are never in the same region.** The analysis state is rendered on the artifacts table row
   (level 1) and in the `EvidencePanel` (the persistent `w-1/3` right region). Producibility is
   rendered only inside the drill-down's tree column and viewer body (the `flex-1` left region,
   level 2). **No Phase 7 surface renders an analysis-state word.**
2. **They are never in the same component, and the rule is testable.** No DOM subtree containing a
   `data-defminer-status-badge` node, or any string from `SCAN_STATE_PRESENTATION` /
   `SCAN_LIFECYCLE_PRESENTATION`, may contain a `data-defminer-source-producibility` node — and the
   converse. This is assertable per test over the rendered subtree, in the same shape
   `EvidencePanel.spec.ts` already asserts the no-`title`/no-`data-*` absolute.
3. **The degraded producibility state is a SENTENCE in the viewer body, not a badge.** D-22's copy
   explains an absence, and a one-word badge beside another one-word badge is the confusion this
   mechanism guards against. The single **word** appears only in the 32px tree row, which cannot
   hold a sentence — and the tree row is a surface where no other state word exists, so there is
   nothing for it to be confused with. **Binding form of that rule: the producibility word may not
   appear on any surface that also renders an analysis-state or lifecycle word.**
4. **The producible case renders NOTHING AT ALL.** No word, no tone, no element. A vocabulary whose
   common member is invisible cannot be confused with one whose every member is visible — and it
   also keeps the tree quiet, which is what makes a tombstone legible when one appears.

### The debt, declared rather than smuggled

`07-CONTEXT.md` D-11 already ships a slice of ERR-02/OBS-02 ahead of Phase 2, and instructs that
this be declared. **Defining a producibility axis widens that pre-emption**, and the honest form is
one paragraph in the plan and in `07-VERIFICATION.md`: Phase 7 defines an axis OBS-02 does not yet
own; if Phase 2 rules that producibility belongs inside one vocabulary, **this column is what
changes**, and the change is a `migrations.ts` forward step plus one presentation map.

mechanism 1 of `## Three Vocabularies Now` doing its work for free.**

**Entering the drill-down does not clear the artifact selection and does not close the evidence
panel.** Three consequences, all of them wanted: the parent's analysis state stays on screen while
the operator reads its recovered source; the coalescer's triage lock stays engaged, so newly
recovered sources accrue into the coalescing pill instead of shifting rows under a reader; and
leaving the drill-down returns to the artifacts table with the same row still selected.

**Leaving:** **Back to artifacts**, a `surface`-toned bordered button in the drill-down header, at
`px-2 py-1` Label role, with `FOCUS_RING_CLASS`. `Escape` from anywhere in the drill-down does the
same. It never navigates away from the page and never changes the active tab.

### 2. The `Sources` column on the artifacts table (the drill-down's only entry point)

`05-UI-SPEC.md`'s table contract fixes four columns in order and leaves the entity-specific columns
to the phase that defines them. Phase 7 adds one, after the four:

| Property | Value |
|----------|-------|
| Header | **Sources** (Label role) |
| Cell — count known and ≥ 1 | The grouped integer, rendered as a `<button>` with `aria-label` **Browse {n} recovered sources**, `surface`-toned, `FOCUS_RING_CLASS`. Activating it enters the drill-down. |
| Cell — count known and 0 | The literal `0` in `text-surface-400`, **not a button**. |
| Cell — count NOT known | **Nothing.** Empty cell. |

**The zero-versus-unknown distinction is the whole point of the column and it is the one thing that
must not be collapsed.** `App.vue`'s own rule is that a still-resolving count renders as absent and
never as `0`, because a zero reads as "nothing found here" and stops the operator opening the one
row that had the finding. A *resolved* zero is a real, useful fact — this bundle carried no inline
map — and it renders as `0`. An *unresolved* count is not a fact and renders as nothing.

### 3. The source tree (D-06, O-08)

**Built in the frontend, from the verbatim `sources` strings, by the five-step pure function O-08
fixes** — classify the prefix shape by `indexOf`/`startsWith` (never a regex); split on `/` **and**
`\`; resolve `.` and `..` **clamped at the root and marked, never followed and never dropped**;
sanitise each **segment** through `forCellText`; disambiguate duplicate sibling labels **by
position, never by renaming** (no Unicode normalisation, no case folding — SPIKE-12 measured NFD/NFC
and case-only collisions in the wild, and collapsing them destroys two distinct files into one node).

**The node is `{ label, sourcesIndex, degraded }` and `label` is NEVER the identity.** Every read
that needs the real string goes back to the stored row by `sourcesIndex`. Losslessness is therefore
**structural — the normaliser has no write path** — and the spec that proves it is a round-trip
assertion: for every fixture, the stored verbatim string is byte-identical before and after tree
construction.

**`node:path` is prohibited on this path**, in any specifier form. SPIKE-12 measured `path.resolve`
escaping on 5 of 22 fixtures and `path.normalize` silently rewriting an RTL-override fixture to
`defminer-escape.txt`. The normaliser is hand-written string work over segments — which is also what
makes it testable against the retained fixtures.

**Rendering:**

| Property | Value |
|----------|-------|
| Structure | The tree is flattened to a **visible-node list** and virtualised through `RecycleScroller` at `itemSize` bound to `TABLE_ROW_HEIGHT_PX`. Expand/collapse rebuilds the flattened list. |
| Row | `[indent][disclosure, directory nodes only][label, mono, forCellText][display note][producibility word]` |
| Indent | `sm` (8px) per depth, capped at eight levels (`3xl`, 64px) |
| Disclosure | A `▸`/`▾` text codepoint in the inherited font — **not an icon and not an icon dependency.** It is never the sole carrier: the whole row is a `<button aria-expanded>` whose accessible name is the directory's label, so the glyph is redundant reinforcement. This satisfies `05-UI-SPEC.md`'s ban on icon-only affordances rather than diverging from it. |
| Ordering | By the map's own `sources` index within each parent. **Deterministic, and it matches the evidence** — the order the developer's bundler declared. Never sorted client-side; never sortable. |
| Selection | `surface-700` background, `aria-current`. No accent bar. |
| Duplicate siblings | When two sibling leaves share a display label, **both** carry their index as a Label-role suffix — `app.js · #412`. Only when duplicated; otherwise the index is noise. |
| Display notes | A clamped `..` renders the Label-role note **path clamped**; a truncated segment renders **label truncated**. Both `surface-400`. These are display notes, not a vocabulary — and the viewer header always shows the **verbatim** `sources` entry, which is what makes the losslessness visible rather than merely provable. |
| Producibility | Only when degraded, per `## Three Vocabularies Now` mechanism 4. |

### 4. The source viewer (D-18, D-19, O-02)

**Plain monospaced text, virtualised by line, and nothing else.** No syntax highlighting, no
tokeniser, no highlighter dependency answering to DIST-05's bundle allowlist, and **no import of

|----------|-------|

### 5. The position readout (D-16, MAP-03) and the position strip

The VLQ decode is the one position consumer that exists without detectors, and D-16 puts it in the
**browser** — 167 ms of blocked QuickJS is 167 ms in which live browsing is not being proxied; in a
real browser it is a shrug. D-17 makes that a package-level capability ban rather than a convention.

**The strip is always present at `h-12` under the viewer.** A fixed-height block that appears and
then fills is a flash rather than a skeleton (06's rule), and a strip that is always there is also
where the position feature is discovered.

| State | What the strip says |
|-------|---------------------|
| No line selected | The discovery line (`## Copywriting Contract`) |
| Line selected, positions not yet read | **Reading positions…** |
| Line selected, mapped | The position sentence, with the count of further positions when there is more than one |
| Line selected, unmapped | The no-position sentence |
| Map carries no `mappings` | The no-position-table sentence |
| Decode threw | The decode-failed sentence — **the viewer stays up and the source stays readable** |
| Line truncated | The truncation notice + **Copy full line** |

**Two binding interaction rules.**

- **The position data is LAZY: the viewer must render, scroll and be fully usable before one byte of
  `mappings` has crossed the RPC.** `mappings` is the larger half of the payload and is unused until
  the operator asks for a position. Whether it rides `deriveSource` or a second call is the
  planner's; that it does not block first paint is this contract's.
- **A decode throw degrades this strip and nothing else.** O-01's fourth requirement: `mappings` is
  target-controlled, it never goes in the DOM — it is decoded to integers — but the *decode can
  throw*, and an uncaught throw takes the viewer down with the source still on screen behind it.

## The Four Body States of the Viewer

Mutually exclusive. Each has its own copy row, and **no two may be collapsed.**

| State | Cause | Rendered as |
|-------|-------|-------------|
| **Content** | The reload succeeded and the reloaded body's sha256 matched the recorded artifact digest | The virtualised line list |
| **Gone** | D-23 detected at open that `sdk.requests.get` no longer returns the originating request; the outcome is written once and sticks | The D-22 tombstone sentence, `p-6`, Body role. The tree row carries the word **Gone**. |
| **Changed** | D-24's re-verify found the reloaded body's sha256 does **not** match the recorded digest — the target redeployed | The bundle-changed sentence, `p-6`, Body role. The tree row carries the word **Changed**. **Fail closed: the content is withheld, never transparently re-derived from the new body.** |
| **Could not ask** | The derivation RPC itself failed, timed out, or the backend did not answer | The RPC-failure copy, with **Retry** and **Open Health** |

**The rule that outranks the table, and it is the most important sentence in this document:**

> **A failed call is NEVER rendered as a tombstone, and the frontend NEVER infers producibility.**

D-23's write happens on the backend, only when the reload genuinely returns missing-or-no-response,
and it is permanent. A frontend that painted a timeout as **Gone** would be making a durable-looking
claim from an absence of evidence — the exact defect `App.vue:606-611`'s shipped rule names for the
compat check: *"a call that did not answer is not evidence of a refusal."* The RPC-failure copy
says so out loud, in the operator's words, because this is where a reader would otherwise conclude
the wrong thing.

**A fifth state that lives on a different surface, recorded so it is not looked for here.** A map
that was refused, truncated or malformed produces **no source rows at all** (D-11 records
`scan_state = 'partial'` with its redacted error). That is the *tree's* empty state, not the
viewer's, and its reason is in the `EvidencePanel` at the artifact level where the analysis
vocabulary lives.

## Rendering Safety Contract

**R1–R5 are inherited verbatim from `05-UI-SPEC.md`.** Three deltas and one addition.

### R1 — restated for the viewer, because this is where it earns its keep

`v-html` stays banned by lint at `error` with no per-line disable; `innerHTML`, `outerHTML`,
`insertAdjacentHTML`, `document.write`, `new Function` and `eval` stay banned; no target-controlled
string reaches a `:style`, `href` or `src` binding.

**Every recovered source line is a text node and nothing else.** D-19 means the viewer has no
slicing path at all — **`safety/HighlightSlices.vue` must not be imported by any Phase 7 module**,
and there is no highlighter to tokenise hostile bytes with. The absence of the mechanism is the
control.

### R2 — the third truncation tier

The shipped caps are `TABLE_CELL_MAX_GRAPHEMES = 256` and `EVIDENCE_PANEL_MAX_GRAPHEMES = 2048`.
**Neither describes a source-code line.** `display.ts`'s header requires the cap to be **bound in
the function name** so a call site cannot reach the wrong one by mistyping, so Phase 7 makes two
named additions in the existing idiom rather than passing a fourth ad-hoc number at a call site:

- **`SOURCE_LINE_MAX_GRAPHEMES = 1024`** in `packages/engine/src/sanitise.ts`, beside the other two.
  Four times the cell cap and half the panel cap — distinct from both, so a mistyped constant is a
  visibly wrong render rather than a subtly wrong one. 1,024 monospace characters is roughly 8,600px
  at 14px, far past any window, so the boundary is reached only by lines no editor would call a
  line.
- **`forSourceLine()`** in `packages/frontend/src/safety/display.ts`, beside `forCell` / `forCellText`
  / `forPanel`.

**`forSourceLine` applies R2's four steps with one deliberate, stated exception:**

1. **TAB (`U+0009`) renders as a fixed run of 2 spaces, DefMiner-authored, never derived from the
   file.** Every other C0/C1 control is stripped. Tabs are *source structure* — stripping them
   destroys the indentation that makes recovered code readable — and rendering them raw inside a
   `white-space: pre` row lets the file choose its own column geometry. Two rather than four because
   the source recovered here came out of a JS bundle, where two is the ecosystem default, and a
   narrower stop keeps deeply-indented lines inside the visible column.
2. **Bidi overrides and isolates (`U+202A`–`U+202E`, `U+2066`–`U+2069`) are stripped**, unchanged. A
   hostile map can otherwise make a recovered line read as its own reverse.
3. **Grapheme-safe truncation at `SOURCE_LINE_MAX_GRAPHEMES`**, never splitting a surrogate pair or
   a combining sequence.
4. **`white-space: pre`**, so a line cannot grow the fixed 24px row.

**`forCellText`, never `forCell`, on every one of these surfaces — and the reason is measured in
this repo, on this exact shape.** `display.ts:110-121` records a 4 MiB single-line hostile value at
**99 of 396 frames over budget, max 442 ms, p95 418 ms, scroll 37,395 ms** through `forCell` against
**0 of 396 frames over budget, max 23.8 ms, p95 17.1 ms, scroll 4,010 ms** through `forCellText`.
`forCell` returns `total`, which forces a walk of the whole value. A 4 MiB single line **is** O-02's
case. The wrong call here produces a 37-second scroll.

**The R2 absolute is unchanged and applies per line:** the full untruncated line is **never** in the
DOM, never in a `title`, never in a `data-*`. **Copy full line** reads it from the frontend store
and writes it to the clipboard.

### R3, R4, R5 — inherited, unchanged

R3 governs the manifest export (formula neutralisation, redacted default, the same sanitisation).
R4 has no subject in this phase. R5's rule survives its Phase 6 implementation deletion and binds
here: **no Phase 7 surface displays a filesystem path**, and the one place a path could have
appeared — the download filename — is governed by R6.

### R6 — Target-controlled strings never become filenames (MAP-04) — NEW

**`sources` entries are never used to build a filename, a download name, or any path-like value.**
MAP-04's first clause has no subject under D-07 (nothing is written) and its second clause — *"
`sources` entries from the map are never used as filesystem paths"* — is met by D-12's retained
traversal fixtures as a **static gate proving the value never reaches a path-like sink**, in the
shape of `filesystem-prohibition.spec.ts`. The browser download is the one remaining sink a
`sources` string could plausibly reach, and it is closed here rather than left to a reviewer:

```
{first 16 hex of the source's content sha256}{extension}
```

where the extension is chosen from a **closed, DefMiner-authored allowlist** —
`.ts .tsx .js .jsx .vue .css .scss .json .md`, falling back to `.txt` — matched against the label's
suffix. **No byte of the target's string reaches the filename.** Assertable mechanically: the
generated name matches `^[0-9a-f]{16}\.(ts|tsx|js|jsx|vue|css|scss|json|md|txt)$`, with a firing
fixture (a traversal-shaped label) and a legal fixture, per the gate family's own shape.

**Carried upstream as amendment A7** — the R-series continues at R6, because "a target string is
data, never a destination" is the same principle R1's `<a href>` clause already states for URLs, and
a later phase that offers any download inherits it.

## Data & Interaction Contract

**Inherited from `05-UI-SPEC.md § Data & Interaction Contract` and `06-UI-SPEC.md`'s amendments
A2–A4.** The deltas:

### The source list read, and why the tree is loaded eagerly

The tree is a **hierarchy over the whole set**, and `05-UI-SPEC.md` bans presenting a subset as the
whole set — that is the same defect its client-side-sorting ban exists to prevent. So:

| Property | Value |
|----------|-------|
| Read shape | Keyset (cursor), never `OFFSET`, following `reads.ts`'s deterministic tie-breaking — the shipped shape, not a new one |
| Page size | **100 rows**, unchanged |
| Load policy | Pages are drawn **eagerly to the bound**, not on scroll. A source row is metadata only — label, index, digest, byte length, producibility — and carries no content, so the whole set for one artifact is small even when its count is large. |
| Bound | **2,000 rows** (U7-1) — the shipped in-memory window number, reused rather than invented |
| Over the bound | The tree renders what it has and **says so in words**, in the U6-1 shape: *"Showing the first {bound} of {total} recovered sources, in the order this map declares them."* Never silently truncated. |
| Sorting | **None, ever.** The map's declaration order is the evidence. Not sortable, not re-orderable. |

**Why a bound is needed at all:** MAP-05's hostile set includes "millions of tiny sources", and at
the 6,291,456-byte decoded ceiling a map can declare hundreds of thousands of `sources` entries.
A tree built over an unbounded node list is an unbounded flattened array.

### Virtualisation geometry — the first surface with two scrollers

| Scroller | `itemSize` | Bound to |
|----------|-----------|----------|
| The tree | 32 | `TABLE_ROW_HEIGHT_PX` (`safety/display.ts`), **unchanged and re-read, never restated** |
| The viewer | 24 | `SOURCE_LINE_HEIGHT_PX`, new, declared beside it; `h-6` added to `ROW_HEIGHT_CLASSES` as a **literal** |

Both are `RecycleScroller`, both bind `itemSize` to a constant rather than a literal, and **neither
is nested inside the other** — they are siblings in a `gap-4` flex row. `InventoryTable.spec.ts`
already asserts `itemSize` against its constant; both new instances get the same assertion.

### The `mappings` string over the RPC

**No new transport and no new bound.** O-01 settles it by construction:

```
decoded map JSON  ≤  ⌊PASSIVE_MAX_BYTES × 3/4⌋  =  6,291,456
mappings          ⊂  map JSON
∴ mappings        <  6,291,456  <  8,388,608 = MAX_RPC_PAYLOAD_BYTES
```

with ~2.1 MiB of slack before the announcement prefix and the surrounding JS are subtracted. **Assert
the inequality, not the number it currently evaluates to** — it must go red the day
`PASSIVE_MAX_BYTES` is raised, which is the only way the composition can break. A map over
`MAP_MAX_BYTES` is **refused, never truncated**: a truncated VLQ stream decodes to *wrong positions*,
not to an error.

**Residual, inherited not created:** the 8 MiB figure is a project budget, not a measured Caido
ceiling — `export.ts:115` says so verbatim, and `exportInventory` already ships 7.00 MiB responses
under the same assumption.

### Events, coalescing and the triage lock

- Phase 7 **appends** its entity category to `INVALIDATION_CATEGORIES`, per that list's own rule
  that entity categories are added by the phase that adds the table. The payload stays the four
  scalars: **no rows, no content, no target-controlled bytes.**
- **The triage lock governs it, unmodified.** While an artifact is selected — which it is for the
  whole life of the drill-down — newly recovered sources accrue into the coalescing pill and apply
  on **Refresh**. A tree re-ordering under a reader mid-file is the same defect the lock was written
  for, one level down. **No exemption is taken and neither `triageLocked` early return is touched.**
- The 500 ms trailing window and the 2-reactions-per-second cap are unchanged.

### What the drill-down does NOT change

- **`App.vue`'s `TABS` list is byte-unchanged.** No sixth tab (D-21).
- **`exportTable` is unchanged.** It stays computed from `activeTab`, so the toolbar's **Export
  inventory** still means the artifacts inventory while the drill-down is open. The manifest is
  reached by its own scoped CTA — see `## Named Conflicts`.
- **The `EvidencePanel` is unchanged**, still `w-1/3 shrink-0`, still mounted unconditionally.
- **`assertColumnContract` is not called on the tree**, and that is obedience, not divergence:
  amendment A4 already scopes the table contract to the virtualised, keyset-paginated **entity**
  tables, and the tree is a hierarchy of one label, not a column matrix. The **`Sources` column
  added to `ArtifactsTable`** *is* in scope and keeps that assertion green — it is DefMiner-computed
  and is not marked `targetControlled`, so the exactly-one count is unchanged.

### Accessibility

## Visual Hierarchy

**Focal point in the drill-down: the recovered source text itself.** Everything else recedes, and
the colour section is what makes that true — nothing on these surfaces is accent-toned except a
focus ring.

Order of visual weight, strongest first:

1. **The code lines** — Body role, `font-mono`, inherited foreground. The largest area, the highest
   contrast, and the only content the operator came for.
2. **The viewer header's source label** — Heading role, `font-mono`. The answer to "what am I
   reading", once, at the top.
3. **The selected line and the selected tree node** — `surface-700` background. Position, not
   emphasis.
4. **The tree labels** — Body role, `font-mono`, at `sm` indents. Navigation, quiet.
5. **A producibility word, when one is present** — Label role, `surface-400`. **Deliberately quiet.
   It is an absence, not an alarm**, and its rarity is what makes it legible: it appears on almost
   no rows, so an operator's eye finds it without it needing to shout.
6. **The line-number gutter** — Label role, `surface-400`, on `surface-800`. Present for reference,
   never for reading.
7. **Chrome** — the three `h-12` header strips and the position strip, `surface`-toned with
   `surface-600` borders, exactly as every shipped strip on this page.

**What is deliberately NOT emphasised, and why.** The tombstone sentences are Body role in a `p-6`
block with no colour and no badge. They are the most *interesting* thing on the surface when they
appear, and rendering them as an alarm would be wrong twice: a tombstone is not an error, and
`## Three Vocabularies Now` mechanism 3 requires that they read as an explanation rather than as a
status.

## Named Conflicts

Two. Both are stated here rather than worked around silently.

### Conflict 1 — the toolbar's Export CTA cannot address the drill-down

- **The Phase 5 rule:** *"Primary CTA (page toolbar): **Export inventory** — opens the redaction
  dialog, never exports directly."* One export entry point, in the toolbar.
- **The shipped implementation:** `exportTable` is computed from `activeTab` (`App.vue:472-476`) —
  `observations` when that tab is active, `artifacts` otherwise.
- **The conflict:** the drill-down is a state *within* the Artifacts tab, not a tab. `activeTab` is
  still `artifacts` while the operator is reading recovered source, so the toolbar CTA would export
  the **artifacts** inventory from a screen showing sources. Making the toolbar address it would
  mean deriving the export table from something other than the active tab — a change to shipped,
  asserted behaviour, on a control whose whole ceremony is about the operator knowing exactly what
  leaves the tool.
- **The resolution, and it satisfies both:** **the manifest gets its own scoped CTA — Export source
  manifest — in the drill-down header, opening the shipped `ExportDialog` with the sources table.**
  The toolbar CTA, `exportTable` and every shipped export assertion are byte-unchanged. There is one
  export **mechanism**, one redaction ceremony and one `danger` confirmation; there are now two
  places to start it, each naming what it will export. **The spirit of the Phase 5 rule — the
  operator always knows exactly which rows are leaving and in what form — is strengthened by this,
  not weakened.**
- **What the planner owes:** the divergence from "one export CTA, in the toolbar" is stated in the
  plan in those terms rather than smuggled. And U7-3: the dialog's heading must name what the CTA
  named.

### Conflict 2 — the fifth vocabulary-separation mechanism breaks

- **The Phase 5/6 rule**, quoted from `contract.ts:101-113`: the fifth mechanism keeping two closed
  state vocabularies apart is that **no surface renders both**.
- **The conflict:** the drill-down renders the parent artifact's analysis state and each recovered
  source's producibility in the same view. There is no arrangement of D-21's drill-down in which
  that is false, and there should not be — the analysis state is the context that explains an empty
  source list.
- **The resolution:** the mechanism is **replaced, not exempted**, by four binding requirements —
  different regions, different levels, a testable no-shared-subtree rule, a sentence rather than a
  badge for the degraded case, and **nothing at all** for the common case. Full text in
  `## Three Vocabularies Now`. **The other four mechanisms transfer unchanged and are not weakened.**
- **What the planner owes:** the O-07 pre-emption paragraph, in the plan and in
  `07-VERIFICATION.md` — Phase 7 defines an axis OBS-02 does not yet own, and if Phase 2 rules
  otherwise, this column and one presentation map are what change.

**One thing that looked like a conflict and is not**, recorded so it is not re-litigated: **the
second fixed row height.** `05-UI-SPEC.md` fixes the *scale* and assigns the `xl` step a usage; a
second virtualised geometry at a different step on the same seven-value scale is an addition to a
usage column, not an exception to the scale. **Exceptions remain none.** That is amendment A5.
