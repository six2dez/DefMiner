<objective>
Close the two peripheral findings that both let a value change type or meaning on its way out of the
plugin.

- **LO-04** — `redactUrlForExport` cuts at the first `?` or `#`. That is right for a URL, where those
  characters begin the query and the fragment. A `sources` entry is not a URL in general: the argument
  at the `EXPORT_COLUMNS.sources` call site says it is "URL-SHAPED BY CONSTRUCTION", which holds for a
  `webpack://` prefix and not for the path body. `src/components/Button#new.tsx` exports as
  `src/components/Button` plus the withheld marker — silently discarding a legal filename tail and
  telling the reader a query was withheld when there was none.
- **LO-05** — `snapshotCounters` walks with `Object.entries`, which yields index keys for an array, so
  an array-valued counter silently becomes an index-keyed object and the `as Counters` cast hides it.
  Nothing is broken today because no member is an array; the function is generic and the failure would
  be a health payload whose field is the wrong JSON type with no error anywhere.

Purpose: both are about a value that arrives at the operator meaning something other than what it
meant at rest. Neither is a leak — LO-04 over-redacts and misdescribes; LO-05 has no live instance —
which is why both are LOW and why both are worth closing now rather than after a member turns into an
array and a manifest tail turns out to have mattered.

Output: a redactor that reports only what it withheld, and a snapshot that cannot change a type.
</objective>
