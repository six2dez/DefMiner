<objective>
Rewrite the `RETENTION_SWEEP_MAX_PASSES` derivation so it computes from the insert side the
repository actually ships, and add the test that can catch this class of drift.

This closes **G-07-1 / WR-01**. Commit `59347c3` (plan 07-14) retired the `2 *` compensating
factor from `ROWS_INSERTED_PER_ITERATION_MAX` and updated one docblock, leaving the neighbouring
`RETENTION_SWEEP_MAX_PASSES` derivation computing the pre-fix insert side in three sentences at
`thresholds.ts:166`, `:176` and `:190-191`. `packages/backend/src/store/retention.ts:178-180`
already writes the correct figure, so two files in one repository state different numbers for the
same quantity.

Nothing is unsafe at runtime — 16 over-satisfies the inequality by a wide margin — but the stated
derivation no longer produces the stated constant, and `thresholds.spec.ts:260-281` computes the
inequality FROM the constants, so it is structurally unable to fail on prose drift. That structural
blindness is the real finding: the number was wrong for a full round and every gate stayed green.

Purpose. This is the TRACER for the round. All four gaps in this closure round are the same shape —
a sentence in the repository disagrees with the code beside it, and the test that should have caught
it asserts over the code rather than over the sentence. This plan proves the repair pattern end to
end on the smallest of the four: source prose corrected, a documented-prose-versus-shipped-constants
spec added, the wired vitest gate green. Plans 07-19, 07-20 and 07-21 expand that pattern to the
other three sites.

Output: a derivation that produces 16 as retained headroom over a derived 8, and a spec that fails
the next time a factor is retired and a sentence is left behind.
</objective>
