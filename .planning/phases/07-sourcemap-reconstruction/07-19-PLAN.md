<objective>
Count the depth refusal from what was actually admitted for recursion, and add the pinning case that
proves it.

This closes **G-07-4 / IN-01**. At `consumer.ts:1272-1287` the hoisted D-13 depth gate guards on
`parsed.recovered.length > 0`, but recursion only happens for sources `admitDerived` admits. A map
whose every `sourcesContent` entry is the empty string gives `recovered.length` 3, admitted-for-
recursion 0, and the guard fires true — so `derivedRejected.depth_exceeded` increments for a stage in
which zero recursions were attempted. `telemetry.ts:317-322` states the unit as "one reconstruction
stage that DECLINED TO RECURSE" and adds that a non-zero value always means at least one map-bearing
artifact reached the bound. This corner breaks exactly that claim.

The shipped comment names ONE of the two inaccuracies — that the log message's count over-states — and
misses the counter itself, which shares the same condition. Both are closed here, by the reviewer's
own named fix: decide at the top, report at the bottom, from what actually happened.

Purpose. `07-18` proved the repair pattern for this round on prose. This is the same defect class one
layer down: a counter whose documented unit and whose trigger condition disagree, with no test able to
notice because no fixture drives the corner. The magnitude is small and deliberately stated as such —
one increment per map-bearing artifact against the 781 MD-03's fix removed, and no health surface
carries the counter. It is worth closing because the counter's whole value is that it now carries
information, and a counter that fires on a stage rather than on a refusal carries none.

Output: an `admittedForRecursion` local, a post-loop emission, and a case that is RED against the
shipped code.
</objective>
