<objective>
Decide whether a bundler loader query is analytic content the operator should see or a residual the
redactor should cut, then make the docblock and the code agree with the decision.

This is the SECOND half of **G-07-3 / WR-03**, and the only one of this round's four gaps with a
disclosure direction. `redactSourceLabelForExport` (`export.ts:273-275`) delegates to
`redactUrlForExport` only when `isProtocolShapedLabel` is true. The stated premise at `export.ts:255-256`
— "A label that is not a URL has neither axis" — is false for the ordinary vite and webpack shape
`src/App.vue?vue&type=script&lang.ts`, which `classify()` puts in `relative`. Those tails now export
VERBATIM in redacted mode where they were previously cut at the `?`. **The SAFE mode discloses more
than it used to**, on a premise that is factually wrong, and until plan 07-21 landed the corpus could
not see it.

The counterweight is stated so this is not overread: the value still passes `stripForExport` and
`csvField`, so there is no injection, and a bundler's loader query is not the credential class
`redactUrlForExport` was written for. This is a scope judgement about what a redacted export means,
not a vulnerability.

**The recommendation is option A — split the two axes — on a premise the operator may reject.** LO-04's
real defect was the FRAGMENT axis on a bare path: `src/components/Button#new.tsx` acquired a marker for
a fragment it did not have and lost a legal filename tail. The asymmetry that separates the two axes is
about INTENT, not permission: `?` is a reserved delimiter in URI syntax (RFC 3986) and is rejected by
the Win32 API, so a `?` in a bundler-emitted `sources` label is overwhelmingly a loader or URL artifact
rather than part of a name — whereas `#` appears in ordinary checked-in names such as `Button#new.tsx`,
which is precisely why LO-04's marker there was false. Cutting on the query axis for every label and on
the fragment axis only for URL-shaped ones restores the pre-07-16 safe-mode behaviour without
reintroducing the false marker LO-04 removed.

**The absolute form of that asymmetry is FALSE and this plan does not use it.** `?` is accepted by APFS
and by ext4, which reject only `/` and NUL; it is forbidden by the Win32 API on NTFS and by URI syntax,
not by the storage layer this repository sits on — measured by creating `what?.txt` here, which
succeeded, and already anticipated by `export.spec.ts`'s byte-budget `extra` array, which carries
`src/gen/what?.ts`. A's argument is therefore PROBABILISTIC about what a bundler emits, never absolute
about what a name may contain. **If the operator judges that a `?` can legitimately be part of a source
name, A's marker is not always a true statement and B is the correct choice.**

Purpose. `07-18` proved the repair pattern on prose, `07-19` on a counter, `07-20` on an invariant.
This is the same class where it costs the most to get wrong: a sentence that justifies a narrowing, a
narrowing that changes what an operator's safe export contains, and a 23-label corpus that could not
notice — now 24, so it can.

Output: one direction, chosen at a checkpoint, a premise sentence that is true, and the corpus case
asserted by id in both modes.
</objective>

and webpack shape, so `src/App.vue?vue&type=script&lang.ts` now exports verbatim in REDACTED mode where

**What is actually being decided.** Not whether the narrowing was well-intentioned — LO-04 was a real
defect and the fix for it was right. What is being decided is whether the safe export mode should
disclose a bundler loader query, and therefore whether the sentence justifying the narrowing gets

**The asymmetry that makes option A the recommendation — and it is a PREMISE, not a settled fact.**
`#` is a legal filename character — `Button#new.tsx` is a real file name, which is exactly why LO-04's

delimiter in URI syntax (RFC 3986) and it is rejected by the Win32 API, so a `?` inside a

On that population — the labels a bundler actually emits — a marker beside a cut `?` is a TRUE
statement, which is the constraint LO-04 established.

**Do not accept the stronger version of this, because it is false.** An earlier draft of this plan
claimed `?` is not a legal name character on any mainstream storage layer. That was checked and it is
wrong: APFS and ext4 both accept `?` and reject only `/` and NUL, and this repository is checked out on
APFS. `what?.txt` was created here successfully, and `export.spec.ts` already carries `src/gen/what?.ts`
in its byte-budget `extra` array. Only Win32 on NTFS forbids it.

**So the premise you are being asked to accept or reject is this one:** a `?` appearing in a `sources`
