## Debts discharged in this plan, in its own words

**UI-SPEC Named Conflict 1 — the toolbar's export CTA cannot address the drill-down.** The Phase 5
rule is one export CTA, in the toolbar, opening the redaction dialog and never exporting directly. The
shipped implementation derives the export table from the active tab. The drill-down is a STATE within
the Artifacts tab, not a tab, so the active tab is still artifacts while the operator is reading
recovered source, and the toolbar CTA would export the ARTIFACTS inventory from a screen showing
sources. Making the toolbar address it would mean deriving the export table from something other than
the active tab — a change to shipped, asserted behaviour, on a control whose whole ceremony is about
the operator knowing exactly what leaves the tool.

**The resolution, and it satisfies both:** the manifest gets its own scoped CTA in the drill-down
header, opening the shipped dialog with the sources table. The toolbar CTA, the export-table
computation and every shipped export assertion are byte-unchanged. There is ONE export mechanism, ONE
redaction ceremony and ONE destructive confirmation; there are now TWO PLACES TO START IT, each naming
what it will export. **The divergence from "one export CTA, in the toolbar" is stated here in those
terms rather than smuggled**, and the spirit of the Phase 5 rule — the operator always knows exactly
which rows are leaving and in what form — is strengthened by this, not weakened.
