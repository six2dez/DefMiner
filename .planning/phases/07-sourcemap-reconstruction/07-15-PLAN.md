<objective>
Close three findings that all have the same shape: a claim stated in a docblock and a weaker thing
delivered in the code.

- **MD-03** — D-13's depth gate is re-taken inside `reconstruct`'s preamble for EVERY recovered source,
  so one artifact carrying monaco's 781-source map emits 781 identical `sdk.console.log` lines on the
  proxy thread and drives `derivedRejected.depth_exceeded` to exactly `sourcesRecovered`. A counter
  equal by construction to another counter carries no information, and a health surface reading
  "781 sources rejected: depth_exceeded" describes a bound working as designed as if it were a refusal.
- **MD-04** — `countSourcesForMap`'s docblock states MAP-06's aggregate enforcement as fact ("plan
  07-05's ingest path compares the count and refuses with a reason"). It has no production caller. The
  aggregate half of MAP-06, across repeated ingests, is enforced nowhere.
- **LO-03** — `sources_verbatim` is cut at code unit 4,096, so a label whose 4,095th code unit is a
  high surrogate stores an unpaired surrogate: an invalid UTF-8 sequence in a SQLite `TEXT` column that
  round-trips through the driver and the RPC boundary unpredictably.

Purpose: MAP-06 is a ticked requirement, and its ledger row currently rests on a bound that does not
exist. That is the exact failure mode MD-04 names — a docblock a verifier will cite.

Output: one refusal per stage, an enforced aggregate, and a stored label that is always valid UTF-8.
