<objective>
Ship the retroactive scan as ONE production-quality vertical slice: an operator clicks **Start scan**
on a new Scan tab, the backend inserts a `scans` row, walks exactly one page of
`sdk.requests.query()` under a composed HTTPQL filter, offers every admitted item into the shipped
`BoundedQueue`, advances the persisted position, and the tab shows the counters and the position
date moving.

Purpose: prove the architecture end-to-end on the phase's best early-context tokens. Every later plan
in Phase 6 expands one layer of this slice horizontally. If the slice is wrong — if the position is
not re-derivable, if HTTPQL composition cannot be made safe, if the RPC shape cannot carry the
progress payload — it is wrong after one commit rather than after ten.

Output: a walkable scan. Deliberately thin per layer; each layer is filled out by a named later plan
and no layer is stubbed in a way that would need an architectural change to fill.

**Phase-level declarations this plan makes on behalf of the whole phase, stated out loud rather than
left for a verifier to discover:**

1. **D-11 ships a slice of ERR-02, a Phase 2 requirement.** `init()` moving every `running` scan row
   to `suspended` is ERR-02's rule — *jobs in flight when the process died are detected on startup and
   either resumed or explicitly abandoned, never left permanently `running`* — applied to the one
   table that needs it now. Phase 2 inherits this pattern rather than inventing a second one. The
   implementation lands in plan 06-05.
2. **ROADMAP plan title `06-03: Hosted-file delivery, quotas, orphan cleanup, and storage labelling`
   no longer describes what will be built.** D-17 declines `sdk.hostedFile`, and `HostedFileSDK` has
   no delete and no expiry, so DEPLOY-03's "expiry" and DEPLOY-04's "orphan cleanup" are not
   expressible against that surface. What ships instead is the already-measured chunked RPC download
   (Phase 5's D-04) plus two gates that keep the guarantee true — plan 06-07 — and the honest Settings
   statement — plan 06-08. The ROADMAP's plan list is amended in the same commit as this plan set.
3. **ROADMAP Phase 7's stated dependency on Phase 6 — *"delivery path must exist before we produce
   files to deliver"* — is already satisfied by shipped Phase 5 code** (`store/export.ts` plus
   `frontend/src/components/export-download.ts`). Phase 6 adds no delivery path because one exists.
4. **O-01 is NOT settled and D-17 rests on it.** It is recorded here as a named carried obligation
   owned by Phase 7's first plan: measure whether reconstructed source can live in SQLite within
   QuickJS's memory, by the SPIKE-06 method with external RSS sampling. If the probe is negative,
   Phase 7 re-opens D-17 deliberately rather than working around it.

  <context>
    The ladder is at v4, not v3 — plan 05-07 added two indexes. `scans` is step **v5** and
    `SCHEMA_VERSION` becomes 5.

    The column list, and why each column is decidable now:

    - `project_id TEXT NOT NULL` — first in the PRIMARY KEY, by ordinal.
    - `scan_id TEXT NOT NULL` — caller-minted UUID. `FORBIDDEN_COLUMNS` bans the bare name `id`
      outright because `last_insert_rowid()` is unusable on the pooled connection.
    - `state TEXT NOT NULL CHECK (state IN ('running','suspended','completed','discarded'))` — named
      `state`, never `scan_state`: `analyses.scan_state` already exists over a different closed
      vocabulary and two vocabularies under one column name in one database is the drift shape this
      repo keeps catching.
    - `suspend_reason TEXT` — a closed DefMiner-authored code, never rendered error text.
    - `operator_filter TEXT NOT NULL` — `''` when the operator supplied none.
    - `epoch INTEGER NOT NULL` — D-04's guard value.
    - `last_request_id TEXT NOT NULL` — **the authoritative, re-derivable position.** `''` before the
      first page. O-04 (is a Caido `Cursor` stable across a restart?) is NOT MEASURED and this
      migration must not wait on it: `RequestOrderField` includes `"id"` and HTTPQL's `row` namespace
      has `id` with `lt`, so the position is expressible as HTTPQL over a plain integer that survives
      anything.
    - `last_cursor TEXT` — nullable, opportunistic, an in-process fast path only. NULLed by the
      `init()` sweep. **O-04's probe is not a plan of its own and never was**: it is four lines inside
      plan 06-10's restart leg, in a matrix leg that already restarts the instance for D-22's fourth
      assertion, so it costs one assertion rather than a plan. If it comes back positive the column is
      already there and the in-process fast path widens without a second migration; if it comes back
      negative nothing in the design moves, because `last_request_id` is the authoritative position.
    - `last_created_at INTEGER` — D-14's "now scanning traffic from 14 Aug".
    - `pages_walked`, `seen`, `admitted`, `skipped_done`, `rejected`, `queued` — `INTEGER NOT NULL`.
    - `started_at INTEGER NOT NULL`, `updated_at INTEGER NOT NULL`, `finished_at INTEGER`.

    **Deliberately NOT included:** six per-reason reject columns (they would couple a one-way
    migration to a vocabulary Phases 3/4 will grow) and a JSON blob column (which is exactly what
    `COLUMN_ALLOWLIST` exists to prevent). The aggregate `rejected` lives here; the live per-reason
    breakdown is served from `telemetry.ts`'s retro sub-map. **The accepted cost, stated rather than
    discovered: a completed scan's per-reason breakdown is not durable.**

    Indexes: `idx_scans_state ON scans (project_id, state, started_at)` and
    `idx_scans_one_running ON scans (project_id) WHERE state = 'running'` — a partial UNIQUE index,
    which makes the one-scan-per-project invariant a driver-level failure rather than a
    read-then-write the pool cannot make atomic.
  </context>
