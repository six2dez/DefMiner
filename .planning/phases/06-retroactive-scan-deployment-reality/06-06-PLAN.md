<objective>
Couple retention to the scan state machine in exactly one branch, give `audit` the two kinds a
destructive scan event needs, and put the authoritative size check where the byte count is known good.

Purpose: `sweepRetention` already returns a `deleted` count — but it does NOT distinguish an age-bound
delete from a row-cap delete. Both victim sets are pushed into one array and counted into one field.
D-08 fires on row-cap eviction specifically, because a row-cap eviction while a scan is running means
the backfill is consuming itself, and an age-bound eviction means nothing of the sort. So D-08 needs a
new field on a return shape whose own comment says FIXED SHAPE.

And D-26 adds the SECOND retention exemption this project has ever taken. The first one — `audit` is
exempt from the age bound — is expressed by the ABSENCE of a statement, with the reasoning written
where the missing statement would be, and its closing sentence says any second exemption is a new
decision needing its own paragraph. D-26 cannot be an absence, because it attaches to a STATE and not
to a table. It has to be a predicate, visible in the statement text.

Output: migration step v6, two new `audit` kinds, `rowCapDeleted`, the `scans` sweep with its visible
exemption, the single D-08 branch, and the reload-side size gate.
</objective>

  <name>Task 1: One-way decision — widening `audit`'s closed `kind` CHECK by rebuilding the table (D-16)</name>
  <decision>
    Migration step v6 REBUILDS the `audit` table with a widened `kind` CHECK admitting two new
    members, `scan_discarded` and `scan_suspended_by_retention`. This is a **one-way** decision:
    `audit`'s `kind` is a closed CHECK constraint, SQLite has no `ALTER TABLE … DROP CONSTRAINT`,
    shipped steps are immutable, and audit rows already written cannot be re-kinded.
  </decision>
  <context>
    D-16 gives a retroactive scan exactly two events worth a permanent record — a discard (D-10) and
    a suspension caused by retention evicting the scan's own results (D-08) — and keeps routine
    lifecycle in `scans` under normal retention. That restraint is the point: `audit` is the
    age-exempt ledger Phase 5's D-06 raised the row bound on specifically to preserve
    permanent-consequence records, and filling it with background-job chatter would evict the
    projection records it exists for.

    The shipped `kind` CHECK admits seven members: `triage_set`, `suppression_create`,
    `suppression_remove`, `finding_projected`, `export_raw`, `export_redacted`, `value_revealed`.
    Step v3 created it and step v3 is immutable.

    **The rebuild, and why it is safe despite not being an `IF NOT EXISTS` batch.** Step v2's own
    JSDoc rejected a 12-line table rebuild for the v1 tables on the grounds that it is "a
    multi-statement migration that CAN fail and would therefore strand an open write transaction on
    an unreachable pooled connection". That objection is about a rebuild that CAN fail. The five
    statements proposed here cannot:

    1. `CREATE TABLE IF NOT EXISTS` the replacement with the widened CHECK — cannot fail.
    2. `INSERT OR IGNORE INTO <replacement> (…) SELECT … FROM audit` — cannot fail: the source table
       exists (step v3 created it and the ladder is ordered), the conflict clause makes it idempotent
       on the natural key, and the widened CHECK is a strict SUPERSET of the shipped one, so no
       existing row can violate it.
    3. `DROP TABLE IF EXISTS audit` — cannot fail.
    4. `ALTER TABLE <replacement> RENAME TO audit` — cannot fail: the target name was just dropped.
    5. `CREATE INDEX IF NOT EXISTS idx_audit_at ON audit (project_id, at)` — cannot fail, and is
       required because the shipped index went with the dropped table.

    The alternative considered and rejected: a separate table for scan destruction events. It would
    need its own retention exemption, which would be a THIRD exception, and it would split a ledger
    whose whole value is being the one place an irreversible action is recorded.
  </context>
  <options>

    - **Approve with a different member set** — name the members; each needs a writer in this phase
      or a named owning plan.
    - **Reject** — a discard and a retention-caused suspension leave no permanent record, and D-16

  </options>
