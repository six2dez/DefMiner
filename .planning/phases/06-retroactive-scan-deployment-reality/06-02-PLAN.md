<objective>
Settle O-07 by measurement: does `Body.length` on a response returned by `sdk.requests.get()` and by
`sdk.requests.query()` report the DECOMPRESSED identity byte count, as `SIZE_GATE_SOURCE` measured
for the hook path?

Purpose: `admit()`'s size axis is written against the decompressed count, and observed compression
ratios on this project's own corpus ran to 7.25×. If a stored response reports the wire count instead,
the size gate admits up to 7.25× more bytes than intended **on the retro path only**. SPIKE-08
measured the hook and nothing else — `sdk.requests.get()` and `sdk.requests.query()` appear nowhere in
its method — so this is genuinely open, and it is sequenced here, immediately after the tracer, because
a wrong answer changes the producer.

Output: `scripts/phase6/o07-body-length.sh`, a schema for its result artifact, a fast artifact gate,
and one recorded run.

**The disposition is designed in advance so the answer cannot block the phase.** The consumer already
re-reads every queued entry by id through `sdk.requests.get()`, so the authoritative size check
belongs at the reload rather than at the query. Plan 06-06 ships that reload-side gate whichever way
this probe lands; this plan produces the fact, and the fact goes in the record instead of in an
assumption.
</objective>
