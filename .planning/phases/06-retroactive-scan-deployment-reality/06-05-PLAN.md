<objective>
Give the scan a state machine that survives a restart, a project switch and a mis-click, and expose it
as RPCs.

Purpose: FIND-04 requires a scan that reports progress and can be cancelled. D-10 makes cancel mean
PAUSE so a mis-clicked cancel on a multi-hour backfill costs nothing, and makes discard a separate
explicit act. D-04 suspends on an epoch change so nothing is written under a stale project. D-11
sweeps `running` rows at startup so nothing is ever left permanently running.

Output: the full transition set in `packages/backend/src/scan/scans.ts`, its dedicated lifecycle spec,
and the `startScan` / `pauseScan` / `resumeScan` / `discardScan` / `getScanStatus` / `listScans`
endpoints.

**Declared out loud, per `06-CONTEXT.md` § Specific Ideas:** D-11 ships a slice of **ERR-02**, which
`ROADMAP.md` assigns to Phase 2. It is better made here than discovered there. Phase 2 inherits this
pattern — one statement, a reason, and never an auto-resume — rather than inventing a second one.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| frontend → scan lifecycle RPCs | Every state transition intent crosses here, including the destructive one. |
| `init()` → `scans` rows written by a previous process | State inherited across a restart. |
| project epoch → running scan | A project switch changes what a write would mean. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-23 | Tampering | scan state transitions | high | mitigate | The state guard is inside every UPDATE predicate. A caller-side check would be two operations this pooled driver cannot make atomic, and the interleaving it permits is the running walk being reset. |
| T-06-24 | Elevation of Privilege | writes under a stale epoch | high | mitigate | `SUSPEND_ON_EPOCH_SQL`'s `AND epoch <> ?` predicate, called per page. Nothing is written under a stale project and nothing silently restarts. |
| T-06-25 | Denial of Service | a permanently `running` row | high | mitigate | D-11's single-statement startup sweep, run before any scan endpoint is registered. This is ERR-02's rule, shipped early and declared. |
| T-06-26 | Information Disclosure | RPC return strings | medium | mitigate | `suspend_reason` and every rejection are closed DefMiner-authored codes; anything caught goes through `describeError`, which redacts URL-shaped substrings before truncating at `ERROR_TEXT_LIMIT`. |
| T-06-27 | Denial of Service | concurrent scans | medium | mitigate | The partial unique index on `(project_id) WHERE state = 'running'` makes a second start fail at the driver; the producer's re-entrancy flag is the in-process half. |
| T-06-28 | Repudiation | the destructive control | medium | mitigate | Discard is a separate endpoint with its own name, its own JSDoc stating exactly what it destroys, and — from plan 06-06 — an `audit` row. Pause and discard are never the same call. |
| T-06-SC | Tampering | package installs | low | accept | No package is installed; every dependency is pinned by DIST-06 and `06-RESEARCH.md` records zero `[ASSUMED]`, `[SUS]` or `[SLOP]` entries. |
