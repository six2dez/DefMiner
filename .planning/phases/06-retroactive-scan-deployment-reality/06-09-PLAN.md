<objective>
Deliver scan progress to the frontend on one channel, at a rate a human can read, without touching the
invariant that protects durable triage state — **and drive the producer, so there is a walking scan to
report progress about.**

**SCOPE ADDED MID-EXECUTION (operator decision, 2026-08-31) — the producer driver.** Plan 06-05
discovered and STATE.md:649 records that `runScanProducer` is fully built and specced and **nothing
calls it**: wiring it needs `producer.ts` and `test/fixtures/fake-sdk.ts` together with `index.ts`,
and no plan in the original thirteen named those three together. The consequence is that ROADMAP
success criterion 1 — *"A retroactive HTTPQL-filtered scan of existing traffic **runs** with page size
20…"* — is unmet: the cancel/resume half exists and is tested, the **runs** half does not. The
operator was shown three options (a dedicated driver plan, folding here, or gap-closing after
verification) and chose to fold it here, because this plan already owns `producer.ts` and
`api/spec.ts` and progress cannot be delivered from a scan that never walks.

Concretely, in addition to the progress work below:
- Widen the plugin's SDK typing so `sdk.requests.query()` is reachable from `init()`. `index.ts:388`
  takes `PluginSdk`, which types `sdk.api` as `APISDK<Api, Events>` and leaves the rest — read the
  comment at `index.ts:383-386` explaining why the whole `SDK<...>` was not adopted wholesale, and
  widen narrowly rather than adopting it wholesale now.
- Add `requests.query` to `packages/backend/test/fixtures/fake-sdk.ts`, which today implements
  `requests.get` only.
- Construct `ScanProducerDeps` and drive the loop from production code. `runScanProducer` is already
  dependency-injected, so this is wiring, not redesign.
- `completeScan` currently ships with no production caller (06-05) — the driver is what calls it.
- **The watermark gate is not optional.** 06-03 proved that an unthrottled producer silently discards
  the operator's live browsing, because `BoundedQueue` drops the OLDEST entry at cap. Drive the loop
  through `SCAN_BACKPRESSURE_WATERMARK`, and do not regress `producer.spec.ts`'s sustained-backfill
  contract.
- `heldAtWatermark` must reflect `isHeldAtWatermark()` for real once the loop runs (06-UI-SPEC's
  `## Data & Interaction Contract` makes the signal binding).



Purpose: D-15 asks for progress on the existing coalescer as a new category, and the coalescer as
shipped makes that impossible without weakening it — both of its triage-lock early returns are checked
BEFORE the debounce window, so a summary arriving while the operator has a row selected is counted
into the pending map and never applied. A `scans` category added literally would therefore accrue
into the pill and never land, which is exactly what D-15 says must not happen.

The resolution honours D-15's stated reason and replaces its mechanism: progress rides the SAME event
(one backend→frontend mechanism) but is not an invalidation category, and is routed to its own small
leading-throttled store before the coalescer sees anything. **The triage-lock invariant is not
modified, not weakened and not conditionalised.**

Output: the payload variant and its discriminator, the per-page emit, the lifecycle presentation map
and its badge with the prefix-collision guard, the progress store, and the two upstream UI-SPEC
amendments.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend event → frontend | The one wire out of the backend; this plan adds a second payload variant to it. |
| progress payload → rendered strings | Everything on this path must be an integer, a boolean or a closed-vocabulary word. |
| progress store → durable triage state | The boundary the triage lock protects, and which this plan routes around rather than through. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-44 | Tampering | the event payload | high | mitigate | The progress variant carries integers, a boolean and closed-vocabulary members only; the events map is a discriminated union typed against the event-name constant, so an unhandled variant is a typecheck failure. |
