# Phase 6 Plan 11: The Push-down Superset Proof Summary

D-06 discharged as a suite that can fail — and it failed first: the shipped `cont`
clause was measurably a strict SUBSET of `admit()`'s kind axis on Caido 0.58.2, so
the clause moved to the case-folding `like` family and was re-measured to zero
violations.

**Duration:** 47 min (2026-09-01 07:55Z → 08:42Z) · **Tasks:** 3 · **Commits:** 5 ·
**Files:** 7 created, 6 modified

---

## What was built

**A deterministic 27-fixture corpus** (`scripts/phase6/make-pushdown-fixtures.mjs`)
generated into the gitignored `corpus/pushdown/`, driving `scripts/spike/origin.py`
purely through its existing per-path `content_type` sidecar — the origin is
byte-unchanged, because supplying the fixture set as DATA is what that key exists
for. Ten fixtures are the path-and-header edges research named (the uppercase
`.JS` path, the `.mjs` suffix, a URL with no extension at all, a query string, a
fragment, a charset parameter, an uppercase content type, plus the two non-vacuity
fixtures). Seventeen more are generated one per member of the SHIPPED
`SCRIPTISH_MEDIA_TYPES`, extracted from `admit.ts` at generation time — so a
member added later with no fixture is a red test rather than an invisible gap.

**An in-plugin oracle** (`probe/pushdown-superset/`) whose single exported function
walks the stored traffic and calls `sdk.requests.matches(clause, request, response)`
per pair. It contains no media-type list, no suffix test and no notion of what
should have matched; it is a transcript of one evaluator's answers, and it echoes
the clause back out so the artifact carries the bytes that were evaluated rather
than a claim about them.

**A live harness** (`scripts/phase6/pushdown-superset.sh`) that sources
`instance.sh` and `probe-run.sh` unchanged, declares its own pinned `0.58.2`,
owns ports 8963–8964, refuses 8080, reads the clause out of the shipped module by
Node type-stripping, proxies the corpus once, and validates before it writes.

**The join gate** (`tests/phase6-pushdown.spec.ts`, 25 assertions, 0 skipped)
which asserts the recorded clause byte-identical to the imported
`SCAN_KIND_CLAUSE`, applies the SHIPPED `isScriptish` to every recorded entry,
requires every manifest fixture id exactly once and no extras, names the markup
fixture as the non-vacuity negative, and names the case-folding fixture in its own
test so a regression reads as itself.

## The finding: `cont` is case SENSITIVE, and the docs say otherwise

The first recorded run put the shipped clause in front of Caido's own evaluator and
got FALSE for two responses that `isScriptish` ACCEPTS:

| Fixture | Served | `isScriptish` | shipped `cont` clause |
|---|---|---|---|
| `/F02-UPPER.JS` | `application/octet-stream` | accepted | **did not match** |
| `/f08-upperct.bin` | `Content-Type: TEXT/JAVASCRIPT` | accepted | **did not match** |

The HTTPQL reference states plainly that `cont`/`ncont` are *case insensitive*.
The same probe settled it with paired terms in one instance:

| Term | Matched |
|---|---|
| `req.path.cont:".js"` | `/f01-suffix.js /f05-query.js /f06-frag.js` |
| `req.path.cont:".JS"` | `/F02-UPPER.JS` |
| `req.path.like:"%.js%"` | `/F02-UPPER.JS /f01-suffix.js /f05-query.js /f06-frag.js` |
| `req.path.like:"%.JS%"` | *identical to the row above* |

`cont` returned **disjoint** sets for the two casings. `like` returned the
**identical** set for both — SQLite LIKE's default ASCII folding, measured rather
than assumed. This is exactly the hole 06-RESEARCH § O-03 predicted for
`req.ext.eq` and believed it had closed by moving to `cont`; it had not.

**Why that mattered.** The push-down is an optimisation and `admit()` is the gate,
so an under-matching clause loses artifacts the operator is never told were
missed — a subset returns fewer rows, not an error. Two of DefMiner's seven kind
terms were silently blind to case.

**Re-measured after the fix:** 27/27 captured, **26 matched, 0 superset
violations**, and the single fixture the clause does not match is
`markup-page-with-script-element` — the named non-vacuity negative.

## 06-04's fail-closed property, executed rather than cited

`scan/filter.ts` places the operator's clause LAST and rests a security property on
it (T-06-HTTPQL-INJ): a clause ending in `//` can then only comment out the
composer's trailing parenthesis, so the expression is unbalanced and `execute()`
rejects it. 06-04 proved DefMiner's half and cited the SDK's JSDoc for Caido's.
`.planning/WINDOWS.md` entry 72 named this plan as where that becomes measured.

Two legs on the live build, because one proves nothing:

| Leg | Expression | Result |
|---|---|---|
| control | `(<SCAN_KIND_CLAUSE>)` | did **not** throw, returned 1 item |
| truncated | `(<SCAN_KIND_CLAUSE>) AND (req.host.eq:"a.example" //)` | **threw** `Error: Invalid filter` |

WINDOWS 72 is now `fixed`. Its two companion questions — whether `req.path` strips
the query, and whether `cont` folds case — are also answered: `req.path` DOES
exclude the query (`/f05-query.js?v=2` matched on the path term alone), a fragment
never crosses the wire at all, and `cont` does not fold case.

## Deviations from Plan

### 1. [Rule 1 - Bug] `SCAN_KIND_CLAUSE` was a strict subset of the admission gate

- **Found during:** Task 2, on the first recorded run
- **Issue:** All seven kind terms used `cont`, which the HTTPQL reference documents
  as case insensitive and which is measurably case sensitive on 0.58.2. `/APP.JS`
  and `TEXT/JAVASCRIPT` were admitted by DefMiner and missed by the push-down.
- **Fix:** All seven terms moved to `like` (SQLite LIKE, ASCII case folding),
  measured with paired terms before the change and re-measured after it. The
  derivation in `filter.ts` was rewritten from an argument into a record of what
  was measured, and both packages gained a tripwire asserting the clause contains
  no `.cont:` at all — so `cont` cannot return on the documentation's word.
- **Files modified:** `packages/engine/src/contract.ts`,

  The plan's own prohibition anticipated it ("the clause is corrected in

## Issues Encountered

**One residual, recorded in WINDOWS:** the superset proof is measured on ASCII case
folding only. `isScriptish` uses `String.prototype.toLowerCase` (Unicode-aware);
`like` folds ASCII. The derivation in `filter.ts` argues the gap is empty — no
non-ASCII character lowercases INTO an ASCII `j`, `s`, `m` or into any letter of
the seventeen essences — but that is a derivation, not a fixture. Low value (media
types and `.js` suffixes are ASCII by RFC) and recorded so it is not rediscovered
as a surprise.

**WINDOWS 69 is NOT closed by this plan.** That entry is about O-07's byte-count
verdict not covering a FILTERED `query()` page. This probe's walk is also
deliberately unfiltered — filtering by the clause under test would make "the clause
did not match" and "the pair was never stored" indistinguishable, which is the
whole confound. What this plan does provide is a clause now known to be a superset,
which is the prerequisite a later filtered measurement needs.
