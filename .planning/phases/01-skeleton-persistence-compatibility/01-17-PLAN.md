<objective>
Make the live tier able to fail on CR-07, and make true the one claim of enforcement in this phase that
has no enforcement behind it.

Purpose. The verifier's finding was not only that the code was wrong — it was that **no tier could go
red on it, simultaneously**. Not one of the eight `BARE_CREDENTIAL_SHAPES` contained an `=`, and all
five tracer dye values come from `openssl rand -hex`, and hex never contains an `=`. Plan 01-15 fixed
the unit tier. This plan fixes the live one, which is the only tier that reads the real database file
with `sqlite3` from outside Caido and can therefore tell a write-path redaction from a read-path one.

**The trap this plan exists to avoid, stated before anything else.** Adding a padded dye is not enough
and would reproduce the round-2 failure exactly. Against the defect, a bare query segment ending in two
`=` is stored as the dye minus one byte of padding followed by the redaction marker — so the padded dye
is NOT a substring of the stored value, a fixed-string search returns zero, and the tracer PASSES with a
whole credential in the column. The absence has to be asserted on the PADDING-STRIPPED CORE, because
padding carries no information and the core plus one re-pad plus one `base64 -d` is the credential.
Every assertion, and the secret sweep, must be written that way or this plan adds a dye that cannot
fail.

**WR-21 is the second half, and it is this phase's signature defect in one sentence.** The tracer's
header says that a literal in that file is a bug and that a `grep -c` for the superseded one returning
zero is how that is enforced. Nothing in the repository performs that grep. A search for the script's
own name over `*.ts`, `*.mjs`, `*.sh` and `*.json` outside `.planning/` returns seven hits and every one
is prose. The verifier confirmed it independently. It is worse than WR-15, which was a stale literal a
reader could see was stale: this is a claim that a check EXISTS, which is the claim a reader will not
re-verify, and it sits in the file whose entire purpose is producing citeable evidence. Either write the
gate or delete the sentence. This plan writes the gate.

Output: a live fixture carrying a padded credential on both sub-branches of the rule, assertions that
can see it, an instrument that reports what it measures, a real gate behind a claimed one, and two
committed runs — one pass and one deliberate failure against the real database file.

**Why wave 17, last, and why serialised.** It needs plan 01-15's redaction branch landed — asserting a
padded dye is absent from the column before the branch is fixed is asserting a thing that is not true
yet — and it needs 01-16's gate widenings landed and green, because a live run costs a full Caido launch
cycle and a suite that is red for an unrelated reason wastes it. Plan 01-14 recorded that lesson: the
live tier needs the tree quiet. And the serialisation reason every gap-closure plan since 01-09 has
recorded still applies — this plan runs a deliberate MUTATION against the shared tree, and a concurrent
plan's red is indistinguishable from its own.

**Why there is no separate `type="tracer"` task.** `TRACER_MODE` is on and this whole plan IS the
phase's tracer at its widest: one proxied request through a real Caido into the real database file, read
back from outside it, with a committed failing mutation. Task 1 widens what it proves and task 2 runs
it. Manufacturing a narrower tracer task inside a plan that is one would prove less than the plan
already does.

**What this plan deliberately does NOT do.** It does not touch `tests/phase1-load.spec.ts:34`,
`tests/phase1-runtime.spec.ts:18` or `packages/backend/src/compat.ts:43`, each of which pins a
superseded build. That is not drift: those three pin the build every Phase 0 threshold was MEASURED on,
so re-running `spa-load.sh` or `runtime-answers.sh` on a newer build fails loudly rather than silently
rebaselining a threshold artifact. Decision P7-D5 records that `P1_EXPECT_VERSION` is a HARNESS DEFAULT
and that no Phase 0 number has been re-measured on the newer build; aligning them would delete the
loud-failure net. It does not touch `scripts/ci/check-bundle-imports.mjs`, which answers "measured
loadable" and not "permitted" (P9-D2). It does not re-litigate the userinfo limit of the live tier —
`curl` lifts `user:pass@` into an `Authorization: Basic` header before the request line exists, that is
MEASURED per run and recorded in `grammar-reachability.txt`, and the verifier accepted the handling as
adequate. It does not regenerate `01-VALIDATION.md`'s EXTENDED evidence: pointer amendments with a dated
note only, evidence never rewritten. It does not fix the STORE-03 ledger collision, a recorded deferral
with an owner. It modifies no plan 01-01 through 01-16, and no `01-VERIFICATION.md`, `01-REVIEW.md` or
`01-UAT.md`.
