<objective>
Close WR-25 and IN-21: two gates whose failing path has never run, one of which is the gate this phase
built last round to stop exactly that.

Purpose. Plan 01-17 wrote the no-version-literal gate that the tracer's header had claimed for two
rounds and that nothing performed. The gate is real, it is scoped, it reads the script's whole text
including comments, and its non-vacuity assertions are correct. And its DETECTION predicate has never
executed its true branch anywhere in the suite:

```
const hits = (tracerText.match(DOTTED_NUMERIC) ?? []).filter(
  (run) => run.split(".").length === 3,
);
expect(hits, …).toEqual([]);
```

`scripts/phase1/tracer-e2e.sh` carries a two-component sleep interval and five four-component loopback
addresses, and no three-component run at all. So the filter never returns a non-empty array, anywhere.
Break the predicate in any of the ways the review enumerates — comparing against four, comparing
greater-or-equal, dropping the empty-array fallback, using a search instead of a match, tightening the
pattern to require a leading letter — and the gate stays green forever while enforcing nothing. The two
non-vacuity assertions guard a different property entirely: that the right file was read and is
non-empty. They cannot see an inert predicate.

**Every other gate this phase built avoids this, and the exception is instructive.**
`outbound-prohibition.spec.ts`, `error-redaction.spec.ts` and `observations.spec.ts`'s
`auditPatternUse` all export a pure function and run its failing path against a synthetic fixture. The
WR-21 gate is the one that does not — and its subject is a file whose header states at length that a
gate whose failure path has never run is a gate nobody has tested, and that a
green-because-it-cannot-fail gate is the shape this phase has already had to remove four times. The
verifier confirmed the predicate works by running the filter by hand. That confirmation is real and it
is not in the repository, which is precisely the distinction this round exists to hold.

**IN-21 is the same defect wearing different clothes, in the artifact a reader cites.**
`padded_segments_reached` at `scripts/phase1/tracer-e2e.sh:819` is `bool(raw_rows) and all(… for r in
raw_rows if "?" in r)`. The `bool(raw_rows)` guard catches an empty row list but not the case where
every row lacks a `?` — the generator is then empty, `all()` returns `True`, and the run writes into
`grammar-reachability.txt` that the padded grammar REACHED the plugin while having measured nothing.
It is unreachable in a passing run because a segment-count check fails first, which is why it is INFO
and not a warning. But its truth should not depend on another assertion having already failed, and the
note it writes is committed evidence. Its two siblings, `pathparam_reached` and `userinfo_reached`, are
substring tests over the whole blob and are non-vacuous by construction — this is the only one of the
three with the shape.

**SEVERITY, STATED HONESTLY.** Neither finding is a live exposure and neither touches shipped source.
WR-25 is a gate that could silently stop enforcing; IN-21 is an evidence note that could be true by
accident. Both are prospective. No sentence written by this plan may suggest otherwise.

Output: a detection predicate with an executed red proof on the real input, a reachability predicate
that cannot measure nothing, and a dated pointer amendment on the runs that predate the fix.

**Why wave 22, last, and why serialised.** It needs the tree quiet: this plan plants a literal into a
committed script and breaks its own predicate five ways in turn, while asserting whole-suite green, and
a concurrent plan's red is indistinguishable from its own. That is the reason every gap-closure plan in
this phase since 01-09 has been serialised, and it applies most sharply to a plan whose entire method is
deliberate breakage.

**Why there is no live Caido run and why that is the stronger choice, not the cheaper one.** IN-21's
subject is a PURE predicate over a list of strings. Running it standalone over synthetic row sets —
including the empty-generator case that cannot be produced on a passing live run at all — exercises the
branch a live run structurally cannot reach. A Caido cycle here would cost twenty minutes and prove
less. The committed runs from plans 01-14 and 01-17 stand as they are and are amended by pointer.

**What this plan deliberately does NOT do.** It does not touch the three deliberate pins in
`tests/phase1-load.spec.ts`, `tests/phase1-runtime.spec.ts` and `packages/backend/src/compat.ts` — each
pins the build every Phase 0 threshold was MEASURED on, so re-running a threshold harness on a newer
build fails loudly rather than silently rebaselining, and decision P7-D5 records that no Phase 0 number
has been re-measured. It does not widen the gate's scope to `scripts/phase1/env.sh`, whose usage example
demonstrates OVERRIDING the version variable and which plan 01-17 named as deliberately outside the
scan, with the reason. It does not filter comment lines out of the scan — the rule is about evidence
PROSE and that inversion is documented. It does not touch
`packages/backend/src/outbound-prohibition.spec.ts` (plans 01-18, 01-19), `packages/backend/src/store/*`
(plans 01-20, 01-21), or any committed run directory. It modifies no plan 01-01 through 01-21, and no
`01-VERIFICATION.md`, `01-REVIEW.md` or `01-UAT.md`.
