<objective>
Close UAT gap 1: stop `observations.url` persisting query-string values verbatim, and stop the store
layer rendering caught exceptions unredacted.

The operator's decision at UAT was **redact at write** — keep the path and the parameter *names*,
replace the *values*. Parameter names carry analytic value (knowing an endpoint takes an
`access_token` parameter matters); values are credentials. Today `normaliseObservedUrl` strips only the
fragment, so a signed URL is written in full and kept for 90 days in a database `db.ts` documents as
never garbage-collected, surviving project deletion, and surviving force-reinstall — while
`telemetry.ts` already redacts that identical value out of a 240-character error string before it
crosses the RPC. **The durable store must not be looser than the transient channel.**

Purpose: `01-RESEARCH.md`'s threat table claims "Phase 1 creates no column that can hold a secret.
Enforce by *absence*", and `schema.spec.ts` claims a stolen copy of the plugin database is "a list of
URLs, digests and byte counts, not a credential dump". A query string is a column that can hold a
secret. Both claims are false today; this plan makes them true rather than deleting them.

Output: a redaction at the write path with its own spec, the same discipline applied to every store
module that renders a caught exception, a static gate that fails when either is undone, and — the
part that makes this a gap-closure and not a code change — plan 01-01's `must_have` truth #2 amended
so the plan and the code state the same policy.

**Why there is no leading `type="tracer"` task.** `TRACER_MODE` is on, but this plan modifies shipped
code rather than proving a new architecture. The thin end-to-end slice already exists —
`scripts/phase1/tracer-e2e.sh` — and it cannot assert the new shape until the code produces it, so a
tracer task placed first would necessarily fail. The tracer is therefore task 3, positioned where the
dependency actually is; it is still the end-to-end proof, and it is still the assertion that closes
the truth.

**Sizing note, stated rather than hidden.** Task 2 touches seven files, above the five-file guidance.
Six of those are the SAME one-line edit — swapping a bare exception render for `describeError` — and
splitting six identical mechanical edits across two tasks would separate the fix from the gate that
proves it, which is the pairing this phase has been bitten by losing four times. The seventh file is
the gate itself. Accepted deliberately.

**One file is deliberately NOT in scope, and this is the reason.** `packages/backend/src/compat.ts`
and `packages/backend/src/hooks/passive.ts` also render caught exceptions with a bare `String(e)`
truncated to 160. They are outside the store layer, they are not named in the UAT gap, and the gate
in task 2 is scoped to `packages/backend/src/store/` so it will not flag them. Left alone on purpose;
they belong to a later cleanup pass alongside `01-REVIEW.md`'s IN-01…IN-07.
</objective>

    two accidents. Deliberately carries no length, no hash and no fingerprint of the original: a

    replaced regardless of what it was, so a second pass produces the same bytes.
