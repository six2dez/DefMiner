<objective>
Close CR-07: a query or path segment that is entirely a credential and contains an `=` is parsed as
`name=value`, and the credential is written whole into the half the policy keeps. Close it in the code,
in the fixtures that were structurally incapable of seeing it, and in the three artifacts that assert
it cannot happen.

Executed through the shipped `normaliseObservedUrl`, independently by the code reviewer and by the
verifier: `?dXNlcjpwYTU1dzByZA==` stores as `?dXNlcjpwYTU1dzByZA=<redacted>`. Padding carries no
information — re-pad the retained name half, run `base64 -d`, and a whole HTTP Basic credential comes
back byte-for-byte out of a column `db.ts` documents as never garbage-collected, surviving project
deletion and surviving force-reinstall. `QUERY_NAME_MAX = 64` does not bound it: standard base64 of a
32-byte secret is 44 characters, comfortably inside the retained name. Because
`redactDelimitedSegment` is deliberately THE one shared helper, the identical hole exists on the `;`
path-parameter delimiter — one policy, two delimiters, one defect.

Purpose. **This is the same failure shape as the original UAT bug, reached through a different door: a
claim wider than its enforcement, with no tier able to go red on it.** Two axes moved in opposite
directions in round 2 and this plan keeps them separate, because they are separate. COVERAGE went UP —
the `=`-less half is genuinely closed, mutation-proven against the real database file, and the `;`
grammar reached the column for the first time. CLAIM HONESTY went DOWN — round 1's residual was
DISCLOSED in source as T-01-31, named rather than hidden, while round 2's is CONTRADICTED by three
artifacts: `observations.ts:74-81` (*"no length of bare segment survives and there is no 'shorter than
the bound' left for a future credential format to hide in"* — the construction tests for a BYTE, not
for a NAME), `observations.ts:99-102` (the converse of *"with no `=` it is a value with no name"* is
assumed and is false), and `schema.spec.ts:44-52`, which lists the QUERY grammar as ENFORCED with an
OPEN list naming exactly one other grammar. A second open grammar sits inside the one declared closed,
and an OPEN list is worth more than prose precisely because a reader trusts its completeness.

**And nothing in any tier can currently fail on it.** Not one of the eight `BARE_CREDENTIAL_SHAPES`
contains an `=` — the table was chosen against a rule whose blind spot IS the `=`, which is exactly
what its own header warns about: *"a fixture list that agrees with the implementation measures the
implementation's opinion of itself."* The live tier is blind in the same way and at the same time: all
five tracer dye values come from `openssl rand -hex`, and hex never contains an `=`. Unit fixtures,
live proof and schema claim, blind simultaneously. That combination is this phase's own stated subject
— a gate that passes because it cannot see the violation.

Output: a corrected per-segment rule, an adversarial table derived from the policy question rather than
from the branch under test, and three claims that describe what the code does. The live tier is plan
01-17's; this plan owns the function, the fixtures and the claims.

**Why wave 15, and why serialised.** Rounds 1 and 2 both serialised one plan per wave and the reason
has not changed: every plan in this round deliberately breaks the shared working tree to prove its
gates can FAIL, while each also asserts whole-suite green either side of that break. Two such plans
running concurrently cannot tell their own mutation's red from the other plan's. This plan runs first
because 01-16's gate widenings and 01-17's live runs both need the redaction branch already correct —
asserting a padded dye is absent from the column before the branch is fixed is asserting a thing that
is not true yet.

**Why task 1 is the tracer.** `TRACER_MODE` is on. The thinnest path that touches every layer this plan
modifies is one padded credential going in at `normaliseObservedUrl`, through `redactDelimitedSegment`
on both delimiters, through `recordObservation`'s INSERT, into a real SQLite fixture, and back out
through `listObservations` — asserted on the bytes that were stored, not on the value the function
returned. It is written RED first against the live defect, then made green by the fix. Every later task
expands outward from that proven slice.

**What this plan deliberately does NOT do.** It does not touch the live tracer (`scripts/phase1/tracer-e2e.sh`)
— that is plan 01-17, run once at the end with the tree quiet, which is the lesson 01-14 recorded. It
does not touch any gate in `outbound-prohibition.spec.ts`, `error-redaction.spec.ts` or the pattern
gate — those are plan 01-16, and two plans editing one gate two waves apart is how the second silently
reverts the first. It does not re-litigate the `redactPaths` space residual or the
userinfo-not-provable-through-curl limit of the live tier: both are correctly disclosed. It does not
touch `scripts/ci/check-bundle-imports.mjs` (P9-D2), it does not align the three deliberate 0.57.1 pins
(P7-D5's loud-failure net), it does not fix the STORE-03 / STORE-07 requirement-id collisions (a
recorded deferral with an owner), and it does not re-run the spec-less probe — `01-PROBE.md` is
committed and `COVERAGE.md` is its live ledger. It modifies no plan 01-01 … 01-14, and no
`01-VERIFICATION.md`, `01-REVIEW.md` or `01-UAT.md`.
