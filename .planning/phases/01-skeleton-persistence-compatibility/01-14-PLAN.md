<objective>
Prove, against a real database file on a live Caido, that the grammars plans 01-10 and 01-11 closed are
actually closed — and fix the three things the code review found in the harness that produces the
phase's evidence.

The tracer is the strongest artifact this phase has: `results/runs/README-01-07.md` documents three
runs including a committed MUTATION run in which `redactQueryValues` was removed and eight assertions
fired, and the passing run's `observations-url-raw.txt`, read with `sqlite3` from outside Caido,
contains `…?v=<redacted>&access_token=<redacted>`. That distinction — a read-path redaction versus a
write-path one — is exactly the one that matters, and the artifact settles it against the file.

Purpose. That proof covers ONE grammar. `FIXTURE_URL` uses `$SECRET_PARAM=$SECRET_VALUE` only, so the
live tier has never exercised a bare segment, a `;` path parameter, or userinfo — the three shapes the
two preceding plans changed. A unit case proves the function; only this proves the column, and this
phase has already been bitten once by a spec that could not fail.

Three harness defects travel with it, and each one degrades the evidence rather than the plugin.
`tracer-e2e.sh:5` still names Caido 0.57.1 in its header after decision P7-D5 moved
`P1_EXPECT_VERSION` to 0.58.0, so a reader who checks what the artifact was produced on finds one
version in the header and another in the environment (WR-15). Both `sqlite3` invocations open the LIVE
plugin database read-write while Caido holds it open, which can create `-wal` sidecars, can block on a
lock, and under `set -euo pipefail` discards the whole run after the traffic has already been proxied
(WR-16). And the raw-column assertion only checks that `access_token=` appears somewhere in the
concatenated text, while every RPC row is checked individually — so a run where the RPC returned two
rows and the table held ten would still pass (IN-13).

Output: a widened live fixture, a read-only reader, honest version prose, and two committed runs — one
pass and one deliberate failure.

**Why wave 14, last.** It needs both redaction plans landed: asserting a bare segment is redacted
before 01-10 lands, or a `;` parameter before 01-11 lands, is asserting a thing that is not true yet.
Running the live tier once at the end rather than after each plan also saves three Caido launch cycles
for a path that is not in question. And the serialisation reason every plan from 01-09 onward has
recorded still applies: this plan runs a deliberate MUTATION against the shared tree — it reverts the
bare-segment branch, launches a live Caido and asserts the run fails — while asserting the whole suite
is green either side of it.

**Why there is no separate `type="tracer"` task.** `TRACER_MODE` is on and this entire plan IS the
tracer — the phase's one end-to-end path, run live, against the real database file, with a committed
failing mutation. Task 1 widens what it proves and task 2 runs it.

**What this plan deliberately does NOT do.** It does not touch `tests/phase1-load.spec.ts:34`,
`tests/phase1-runtime.spec.ts:18` or `compat.ts:43`, each of which hard-codes 0.57.1. That is not
drift: those three pin the build every Phase 0 threshold was MEASURED on, so re-running `spa-load.sh`
or `runtime-answers.sh` on 0.58.0 fails loudly rather than silently rebaselining a threshold artifact.
Decision P7-D5 records that `P1_EXPECT_VERSION` is a HARNESS DEFAULT and that no Phase 0 number has
been re-measured on 0.58.0. Aligning them would delete the loud-failure net. It also does not re-run
the spec-less probe: `01-PROBE.md` is committed and `COVERAGE.md` is its live ledger.
</objective>

| Boundary | Description |
|----------|-------------|
| target-controlled URL → durable column | The live tier is the only place this boundary is crossed by a REAL request through a REAL proxy into a REAL database file. Everything else in the phase is a fixture. |
| RPC projection → the database file | The RPC could redact on read while the column stayed dirty. Only the file distinguishes the two, and only a read from outside Caido reads the file. |
| evidence script → the artifact it measures | `sqlite3` opens read-write by default and the plugin holds the same file open. A measuring instrument that can write to its subject is not an instrument. |
| evidence prose → the reader | The script's output IS the phase's evidence artifact. A version named in the header that the harness will not run against makes every number in that artifact unciteable. |
