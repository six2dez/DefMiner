<objective>
Delete the READ-position bound from every place it was written, replace it with the bound measured
from `collect`/`visit`, and split the fixture that claims to pin it so each half is sensitive to the
variable its title names.

Purpose. Round 4 correctly discovered that alias sets chain to arbitrary depth and then wrote a new
limit in place of the old one. The new limit is false. `auditSource` runs `collect(sf)` at ~`:1521`
to completion and only then runs `visit(sf)` at ~`:1726`, so every alias set, every string map and
every poisoned name is fully populated before a single violation is considered. The position of a
USE cannot bound anything. The verifier executed seven shapes the residual calls silent and all
seven report:

```
g.fetch(u);              const g = globalThis;     ["outbound-fetch"]
function z(){g.fetch(u)} const g = globalThis;     ["outbound-fetch"]
sdk[r].send(req);        const r = "requests";     ["outbound-send"]
sdk[k].send(req);        const k = "req"+"uests";  ["outbound-unanalysable"]
s.send(req);             const s = sdk.requests;   ["outbound-send"]
n.sendBeacon(u,d);       const n = navigator;      ["outbound-beacon"]
e("x");                  const e = eval;           ["outbound-dynamic-code"]
```

**And the fixture that claims to pin it is green through a different mechanism than its title
names.** The case at ~`:2798` is titled for a chain read before its root and its body binds `g` from
`a` before `a` is bound. The verifier proved the diagnosis both ways: remove the function wrapper and
move the read last and it is still `[]`; keep the wrapper and bind the root directly and it reports.
The read position does nothing; the inverted bindings do everything. **This is round 3's `:1740-1744`
trap exactly** — a fixture standing as a rule's bound while being insensitive to the variable its
title names — reproduced inside the paragraph round 4 wrote to replace the last false residual.

**The measured bound, stated as the code behaves.** An alias chain resolves to ANY DEPTH provided
each link's DECLARATION appears after the declaration of the name it is grown from, because every
set is grown by consulting the LIVE set during one document-order collect pass. `const a = fetch;
const b = a; const c = b; const d = c; d(u)` reports at four hops. `const b = a; const a = fetch;
b(u)` is silent, because `a` is not yet in the set when `b`'s declaration is read. The USE may sit
anywhere in the file, above both declarations included.

**Why this is the blocker.** The false sentence is not local. The gate file says at ~`:249-252` that
its residual block is copied word for word into three other artifacts and that if they disagree the
code wins. The verifier checked all three and found it verbatim in `.planning/REQUIREMENTS.md:46`,
`.planning/STATE.md:169` and `.planning/WINDOWS.md` at `:40` and `:315`. `REQUIREMENTS.md:46` is the
text CORE-11's `[x]` was flipped against in plan 01-19 and reverted from at `faca607`.

**SEVERITY, STATED PLAINLY AND NOT INFLATED.** Nothing leaks. No outbound call exists in any non-spec
source under either root, the gate runs green over the real tree inside a 1105-test suite, and
`check:bundle` reports the shipped bundle's entire import set as one specifier, `crypto`. CR-09 is a
false disclosure about a test-only gate, not an exposure. No sentence written by this plan may imply
otherwise.

**WHAT THIS PLAN IS AND IS NOT.** It closes the INSTANCE. It is the fifth consecutive round in which
a bound was authored rather than derived, and closing the instance does not close the class — wave 27
owns the mechanism that makes the class detectable rather than reviewer-detectable. This plan says
which of the two it is doing and does not borrow wave 27's claim.

Output: one bound, measured from the code, written in one set of words into four artifacts, with a
fixture pair that can distinguish the claim from its negation.

**Why wave 23, and why serialised.** Every gap-closure plan in this phase since 01-09 has been
serialised for one reason that still applies: each mutates the shared working tree to prove its gate
can fail while asserting the whole suite green, and a concurrent plan's red is indistinguishable from
its own. This plan additionally must land before waves 24 through 26, because each of those narrows

**What this plan deliberately does NOT do.** It does not touch `keyReceiver`'s literal-first ordering
