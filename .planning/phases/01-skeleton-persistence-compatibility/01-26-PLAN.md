<objective>
Bring six disclosures level with the code they describe, close the last collected-binding shape in the
outbound gate, and reconcile three ledger entries that state things the code no longer does.

Purpose. Round 4 landed real fixes and disclosed them inaccurately in six places. None of the six is a
leak; all six are claims wider or narrower than their enforcement, which is the defect this phase has
now corrected five times.

**WR-28 — a property asserted from one chosen offset.** `observations.spec.ts` pins the head-side `;`
residual with `"p".repeat(2010)` and asserts the function is a fixed point there. It is. The verifier
swept the 71 adjacent offsets and found 11 that are not — n=2019 through 2029, where the cut lands
inside the parameter NAME rather than inside the marker, so the second pass sees a `;` segment with no
`=` and redacts it whole. **Secret leaks across n=1900..2100: zero.** The redaction is intact; the
stability claim is not, and it is repeated as a general property in two other files. This is WR-22's
own lesson — do not take the reviewer's cut point, sweep for the adversarial one — applied to the
query-side branch and not to the head-side branch in the same commit.

**WR-29 — a class scoped to the fixture that found it.** Both disclosures scope the non-idempotent
class to a single-segment query. The branch condition is `q === -1 || amp <= q`: there is no `&`
INSIDE the cut. Segment count past the cut is irrelevant. The verifier swept a three-segment query and
found 17 of 71 head lengths are not fixed points. A reader of either disclosure concludes a URL with
more than one query parameter is outside the residual. It is not.

**WR-30 — a bound measured false in one place and left standing in three.** Plan 01-19's second half
discovered that every alias set chains to arbitrary depth and corrected residual (a). Three docblocks
still assert the old bound, each naming a specific source string as silent, and all three report. The
sharpest: `:969`'s exact string is asserted to REPORT by a passing test at `:2782` in the same file,
1,800 lines below it — both currently pass and they cannot both be true. The direction is safe, the
gate reaches further than these three sentences say, and that is exactly the argument
`01-19-SUMMARY.md` itself makes for why it recorded the alias discovery.

**WR-31 — a self-contradiction created by an insertion.** The closing sentence of boundary 2's residual
paragraph in the STORE-07 gate is byte-identical to what it was before round 4; what changed is what it
now terminates. Round 4 inserted an explicit statement that three of the five items are deliberately not
pinned, two lines above a sentence claiming everything on the list is executed below. One word fixes it.

**IN-23, IN-24, IN-25, IN-26** are four small instances of the same shape: a docblock stating a reason
the code does not deliver, a case title claiming a reach the predicate does not have, a re-derived
residual naming two shapes that actually report, and a collector guard that skips two declaration
spellings the header says are covered.

**SEVERITY, STATED PLAINLY AND NOT INFLATED.** Nothing leaks. WR-28 leaks nothing across 200 swept
offsets and no production path applies `normaliseObservedUrl` twice — `recordObservation` runs it once
per row. WR-29 leaks nothing. WR-30 runs in the safe direction. IN-26 is unreachable in the real tree
today. All six are disclosure defects in gates that run green, and no sentence written by this plan may
imply otherwise.

Output: six disclosures that match their code, one more collected binding shape, and three ledger
entries that state what is actually true.

**Why wave 26, and why serialised.** It is the only wave in the round that reaches outside the outbound
gate, and it is deliberately placed after the three that harden that gate so a red in a store file is
never ambiguous with a red in the gate. It shares `outbound-prohibition.spec.ts` with the three waves
before it. It also reverts a production branch in `observations.ts` to prove the sweep can fail, which
needs a quiet tree.

**What this plan deliberately does NOT do.** It does not change `normaliseObservedUrl`'s behaviour: the
head-side instability is disclosed and pinned, not closed, because closing it means dropping back to the
last `/` or to the `?` and truncating an oversized path to its authority — a strictly larger decision
than the one this round has a mandate for, and the same one `observations.ts` already declined with its
reason written down. It does not build the derivation machinery (wave 27), does not amend
`REQUIREMENTS.md` or `STATE.md`, and does not flip CORE-11's checkbox (wave 28). It modifies no plan
01-01 through 01-25, and no `01-VERIFICATION.md`, `01-REVIEW.md` or `01-UAT.md`.
