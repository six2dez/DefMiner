<objective>
Close the three URL grammars that reach `observations.url` outside the `?…&…=` shape plan 01-07
covered, and deliver the half of WR-03's own rationale that WR-03's fix did not.

Four executed counterexamples, reproduced independently by the code reviewer and then by the verifier:

    https://user:pa55w0rd@cdn.test/app.js                        -> unchanged
    https://cdn.test/a.js;jsessionid=SECRETSESSION               -> unchanged
    https://cdn.test/download/eyJhbGciOiJIUzI1NiJ9SECRET/app.js  -> unchanged
    Error: … '/Users/<name>/Library/…/plugins/<uuid>/data.db'    -> crosses the getStatus RPC whole

Purpose: `redactQueryValues` keys entirely off the first `?`, so everything credential-bearing a URL
can carry before it passes through untouched. URL userinfo is HTTP Basic credentials in plaintext.
`;jsessionid=` is RFC 3986 path-parameter syntax and the classic session-token-in-URL shape that Java
servlet URL rewriting still emits. And `describeError`'s `redactUrls` requires a literal `://`, so a
filesystem path — including the operator's OS username — is not URL-shaped to it, which is precisely
why WR-03 was marked fixed while the disclosure it named survived. Three of the four are closed here;
the fourth, a token inside a path segment, is named with its reason and pinned by a case, because
naming a residual is only honest when a test can see it change.

Output: a head redactor composed into the same write path, a path redactor in the error renderer, a
measured linearity bound on the one pattern this code reaches, and a no-pattern gate that can no
longer be defeated — or tripped — by a comment, and that now covers `telemetry.ts` as well, so the
`REDOS_RECOVERY = "kill"` constraint which justifies `redactPaths` being a string scan is enforced ON
`redactPaths` rather than only one file away from it.

Two review findings ride along because they are the same defect in miniature and both live in files
this plan already opens. IN-11: `analyses.ts:210` calls `ERROR_MAX = 300` "unreachable in practice"
when `describeError`'s 240-character cap makes it unreachable ALWAYS — replaced by an executed
`ERROR_TEXT_LIMIT <= ERROR_MAX` assertion, which is the choice `migrations.ts:176-183` reached from the
other direction. WR-13's gate scope: see task 3.

**Why wave 11, serialised behind 01-10.** Same reason 01-09 recorded and 01-10 restated: every one of
the five new plans deliberately breaks the shared working tree to prove its gate can fail, and every
one asserts the WHOLE suite is green. This plan reverts the head redactor, reverts the path redactor
and plants a regex literal into `observations.ts`; 01-10 reverts the bare-segment branch; 01-12 plants
outbound calls into two shipped modules; 01-13 plants an `e.message` render. Concurrently, one plan's
mutation window makes another's whole-suite assertion fail for an unrelated reason, intermittently and
misattributed. `files_modified` overlap with 01-12 and 01-13 is genuinely zero, and the overlap with
01-10 (`observations.ts`, `observations.spec.ts`, `schema.spec.ts`) is real — so the wave guard would
serialise those two anyway, and the reason the OTHER three are serialised is recorded here in words so
nobody reads the empty overlap and optimises it back into a shared wave.

**Why there is no leading `type="tracer"` task.** `TRACER_MODE` is on. The end-to-end path is already
wired and already has a live tracer; this plan changes what two functions on that path do. Plan 01-14
runs the tracer live once, after both redaction plans have landed, rather than each plan running a
20-minute live Caido cycle to re-prove a path that is not in question.

**What this plan deliberately does NOT do.** It does not touch `scripts/ci/check-bundle-imports.mjs`:
per decision P9-D2 that gate answers "which specifiers Caido's QuickJS resolved WHEN MEASURED", not
"which are permitted", and editing its allowlist would silently redefine a measurement into a policy.
It does not close the path-embedded token; see the prohibition above for why, and note that "too hard"
is not among the reasons. It does not touch any row already on disk — settled by P8-D1. And it does
not touch `01-01-PLAN.md` … `01-09-PLAN.md`.

    Add an exported `redactUrlHead(head: string): string` to `observations.ts` and compose it in

    authority begins after the first `://` and ends at the first `/`, `?` or `#` after it. If there is
    no `://`, there is no authority and the userinfo step does nothing. Within the authority, userinfo
