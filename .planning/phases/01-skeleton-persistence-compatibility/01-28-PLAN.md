<objective>
Discharge CORE-11's own enumeration item by item against executed evidence, and flip the box only if
every row is discharged — against wave 27's derived residual, never against a sentence.

Purpose. CORE-11 has been marked complete twice and reverted twice. `e7cc4b6` reverted the first
because the gate could not go red on a shape the requirement's own statement enumerated — dynamic code
construction. `faca607` reverted the second because the eight-row discharge table it was flipped
against contained at least three sentences the verifier falsified by execution, and the falsified text
had been copied verbatim into `REQUIREMENTS.md:46`, which is the text the box was flipped against.

Round 3's ledger was honest and said so in its own words: *"While any shape this requirement's own text
enumerates is unenforced, its stated reach exceeds its executed reach."* Round 4's was not. This plan
exists to make the third checking a different KIND of act.

**What is different this time, stated as three facts rather than as confidence.** First, the residual
the box is flipped against is GENERATED from a registry whose every row is executed against the walk,
and the copy inside `REQUIREMENTS.md` is byte-compared by the same suite run that records the flip —
so the sentence the box rests on cannot be false about the code without a test failing. Second, the
discharge table is assembled by EXECUTION and citation-by-name, one row per surface, each naming the
fixture and the summary where it was observed failing. Third, the flip is conditional and the condition
is enforced by this plan's own structure: an undischarged row leaves the box `[ ]`, and the automated
verify is state-agnostic so the honest outcome cannot fail its own gate. Round 4's plan 01-19 got that
last detail exactly right and it is the one part of round 4 that survived review; it is reused
deliberately.

**What is NOT different, and saying so is the point.** A derived residual makes drift mechanically
detectable. It does not prove the resolver registry complete, it does not prove each row's probes cover
that resolver's domain, and it does not prove the silence list exhaustive. CORE-11's completion is
therefore an argument about ENFORCEMENT plus a disclosed and mechanically-checked residual. It is not a
claim that no shape is missed, and the correction says so in the ledger rather than only here.

**SEVERITY AND SCOPE, STATED PLAINLY.** The must-NOT itself has held every round: no outbound call
exists in any non-spec source under either root, the gate runs green over the real tree, and
`check:bundle` reports the shipped bundle's entire import set as one specifier, `crypto`. Every finding
in this round was prospective gate blindness in a test-only gate. The flip is about enforcement, which
is exactly what both reverts were about.

Output: an item-by-item discharge, a box whose state matches it, and a completion argument a reader can
check without trusting a sentence.

**Why wave 28, and why last.** It cannot run before wave 27, because the residual it flips against does
not exist until then. It cannot run before waves 23 through 26, because four of its discharge rows are
shapes those waves closed. It changes no rule, so it plants no mutation and needs no quiet tree for its
own sake — but it must observe a tree in which every earlier wave's proofs are already committed.

**What this plan deliberately does NOT do.** It changes no rule, no fixture, no resolver and no registry
row. If a discharge row cannot be discharged, this plan does not fix it: it records the row, leaves the
box `[ ]` and names the blocking row as the outcome. It does not hand-edit wave 27's machine-owned span.
It does not close STORE-03's or STORE-07's ledger collisions. It does not run a live Caido. It modifies
no plan 01-01 through 01-27, and no `01-VERIFICATION.md`, `01-REVIEW.md` or `01-UAT.md`.
</objective>
