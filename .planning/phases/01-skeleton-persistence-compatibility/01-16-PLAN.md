<objective>
Close the five warnings and the two verifier-only findings that round 2's review left open, in the
three gates that carry them. Every one is the same defect in miniature: a rule whose stated reach is
wider than its executed reach.

Purpose. Round 2's gates went from "passes its own fixtures" to "survives an adversarial probe it did
not write" — 24 of 28 outbound shapes and 15 of 17 redaction shapes now land, and the verifier
confirmed that by execution rather than by summary. What is left is not a rewrite; it is four rules
that stop one token short of shapes they already almost see, plus two surfaces nobody checked.

- **WR-19** is the sharpest, because the gate states the design rule in as many words — *"could not
  read does not mean clean; that equivalence is the specific defect this rewrite removes"* — and then
  applies it to computed MEMBERS but not to computed RECEIVERS. `sdk["req"+"uests"].send(req)` and
  `globalThis["fet"+"ch"](u)` both return an empty list, while `import("caido:"+"http")` correctly
  reports `outbound-unanalysable` for the same class of unreadable expression.
- **The verifier's two findings the review missed**: `navigator.sendBeacon` is quiet and undisclosed —
  the one outbound global most likely to exist in a host that has none of the other three — and
  `eval`/`new Function` report clean. No AST gate can see inside a string, but banning both outright
  in shipped source is the same two-identifier posture the gate already takes on the constructors.
- **WR-17**: the STORE-07 gate matches `PlusToken` only, so `m += e.message` is invisible, and the
  accumulator never becomes a tracked binding because names grow only through a declaration's
  initializer. `.concat(...)` and push-then-join are the two siblings of a rule it already has. None of
  the three is the disclosed scope-blind or one-hop residual — the offending expression is right there
  in the AST with the binding as an operand.
- **WR-18**: the `analyses.error` allowlist entry names `//cdn/app.js?token=T` as an open residual,
  and `redactPaths` now consumes it whole. The shape that DOES survive — `cdn.victim.example/a.js?token=T`,
  no leading slash — is in neither disclosure. That paragraph is the stated justification for keeping
  the column on the T-01-21 allowlist, so a reader auditing that decision is told the wrong shape is
  dangerous and is not told about the right one.
- **WR-20**: the pattern gate excludes `.replace`/`.split` on the argument that with regex literals and
  `RegExp` construction both banned there is no way to hand them a pattern. That premise holds for
  patterns WRITTEN in the scanned module. An imported or parameter-passed `RegExp` defeats it with none
  of the three banned constructs present. Exposure today is zero; exposure the day someone factors the
  redactors into a shared `patterns.ts` is total, and silent.

Output: four rules that reach what their headers claim, two new surfaces covered, one renderer that
cannot throw, and every ledger cell that cites this enforcement updated to describe the enforcement
that exists.

**Why wave 16, and why serialised.** Same reason recorded by every gap-closure plan since 01-09, and it
has not weakened: each plan in this round deliberately breaks the shared working tree to prove its
gates can FAIL, while asserting whole-suite green either side of that break. Two such plans running
concurrently cannot tell their own mutation's red from the other plan's. This plan runs after 01-15
because both touch `observations.spec.ts` and `schema.spec.ts`, and a gate widening landing on top of
an in-flight fixture rewrite is how one of the two silently reverts. It runs before 01-17 because the
live tier needs the tree quiet and the suite green — 01-14 recorded that lesson at cost.

**Why there is no `type="tracer"` task.** `TRACER_MODE` is on, and the phase's tracer is 01-01; this
plan's own end-to-end slice is 01-15 task 1, one wave back. Every task here operates on a gate that is
already wired into `pnpm test` over real shipped source, so the vertical path — rule, fixture, real
tree, suite — exists and each task widens it rather than opening it. Manufacturing a fifth tracer task
would prove a path that three plans have already proven.

**What this plan deliberately does NOT do.** It does not touch `packages/backend/src/store/observations.ts`
— 01-15 owns that file and this plan's pattern-gate task only READS it. It does not touch
`scripts/phase1/tracer-e2e.sh` or any live run: that is 01-17. It does not touch
`scripts/ci/check-bundle-imports.mjs`, which answers "measured loadable" and not "permitted" (P9-D2).
It does not align the three deliberate 0.57.1 pins (P7-D5's loud-failure net). It does not close the
disclosed CORE-11 residual — a value crossing a function boundary or more than one hop of indirection
— which was accepted as T-01-51 and is stated precisely in boundary 2. It does not re-litigate the

`01-UAT.md`.
