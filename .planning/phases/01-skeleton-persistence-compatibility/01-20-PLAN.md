<objective>
Close WR-22: the CR-07 branch cost `normaliseObservedUrl` its idempotence at the `URL_MAX` cut, a
stated invariant is false, and a separate finding is being deferred on the strength of it.

Purpose. Plan 01-15's padding branch removes the NAME half when the value half is empty. That shortens
the segment, so a `URL_MAX` truncation landing immediately after a `=` is no longer a fixed point. The
reviewer found it at one parameter-name length; the verifier swept independently and found it at
**n=4** — a different cut point, the same mechanism:

```
sweep: parameter-name length 1..40, 900 params, until pass1 != pass2
found at n=4     tailA "=<redacted>&pppp112="     lenA 2048
                 tailB "=<redacted>&<redacte"     lenB 2048
```

and minimally:

```
NEW  "https://x.test/a.js?p133="  ->  "https://x.test/a.js?<redacted>"
OLD  "https://x.test/a.js?p133="  ->  "https://x.test/a.js?p133=<redacted>"
```

Under the old rule the truncated tail re-expanded to the same bytes and the cut fell on the same byte.
Under the new rule the name is destroyed, the string shrinks, and the cut moves.

**Two things make it a finding rather than a curiosity, and both are about claims.**
`redactDelimitedSegment`'s docblock names exactly one accepted cost and then closes by asserting
idempotence in all three branches — true of the helper, false of the composed function the column is
written through, and disclosed nowhere. And the IN-18 pin at `observations.spec.ts:755-791` declines to
fix the severed-marker truncation with the reasoning that the obvious repair "INTERACTS with this
plan's new branch … and the idempotence invariant asserted across every case in this file breaks". The
invariant is ALREADY broken, by that same branch, on an input the repair has nothing to do with. A
finding is being deferred on the strength of a premise that does not hold.

**Why the existing assertions could not see it, which is the reusable lesson.** `CASES` and the
`BARE_CREDENTIAL_SHAPES` loop assert idempotence over `redactQueryValues` on short URLs; `HEAD_CASES`
asserts it over `redactUrlHead`; and the ONLY idempotence assertion over `normaliseObservedUrl` itself
is one 140-parameter fixture whose cut happens to land mid-marker rather than on a `=`. The property
was asserted by a fixture that cannot see its own counterexample. That is why this plan requires a
SWEEP and not another fixture: the sweep is what found it twice, independently, at two different cut
points.

**SEVERITY, STATED HONESTLY.** Nothing leaks. The half that gets destroyed is a parameter NAME, which
policy retains anyway, and no production path applies `normaliseObservedUrl` twice —
`recordObservation` runs it once per row. This is a warning: a stated invariant is false, a new
residual is undisclosed, and a separate finding defers on both. No sentence written by this plan may
imply a live exposure.

Output: a truncation that cuts on a segment boundary, an idempotence case that searches instead of
assuming, an invariant claim scoped to what is true, and the IN-18 pin either closed or re-pinned for a
reason that holds.

**Why wave 20, and why serialised.** It needs plans 01-18 and 01-19 landed and the tree quiet: this
plan runs a deliberate mutation against the shared working tree while asserting whole-suite green, and
a concurrent plan's red is indistinguishable from its own. That is the reason every gap-closure plan in
this phase since 01-09 has been serialised, and it has not changed.

**What this plan deliberately does NOT do.** It does not touch `redactDelimitedSegment`'s three
branches, `redactUrlHead` or the `;` loop — every grammar CR-07 and decision P10-D1 closed stays closed,
and the tables prove it rather than the scope claiming it. It does not revisit decision P8-D1: rows
already on disk were settled by an operator decision at a `blocking-human` checkpoint against a
measured zero, this change governs FUTURE writes only, and it opens no new operator question because it
retains strictly LESS than the current behaviour. It does not re-run the live tracer — no Caido cycle,
no run directory, and the committed runs from 01-14 and 01-17 stand as they are. It does not touch
`packages/backend/src/outbound-prohibition.spec.ts` (plans 01-18 and 01-19),
